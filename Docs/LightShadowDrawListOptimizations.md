# GPUライトカリング・影キャッシュ・描画リスト差分更新（2026-10-24）

エンジン共通処理として3項目を実装した。先行する共通マテリアルキャッシュ／復旧保存と街スクリプト最適化を両条件に含め、今回の3項目だけを切り替えて比較した。

## GPUライトカリング

Forward+の8×8スレッド群内で、64灯ずつの光源のスクリーン上の包含矩形を共有メモリへ置く。以前は64個のタイルスレッドが同じ球の8頂点をそれぞれ投影していたが、光源の投影は群内で一度だけ行い、各タイルは共有済みの矩形との交差を調べる。

ライトの順序、7種類のタグ、1タイル1024灯の上限、保守的な包含球の式は維持した。画面端の余ったスレッドと既に上限へ達したタイルも、群の同期処理には必ず参加する。ゼロ灯ではタイルの個数を0へ更新する。追加バッファ・追加Dispatch・CPUからの画面範囲転送は不要。

Default／Emptyと既存5プロジェクトの計7コピーを列挙し、既存内容が同じことを確認して同期した。DXC 10.0.26100.0でcs_6_0コンパイルに成功した。

## 影のキャッシュ

完成済みの深度配列をフレーム間で保持する。影を落とすメッシュのハンドル・モデルデータ版・インデックス範囲・ワールド行列・IDシード・マテリアルの実際のバイト列、影ジョブのライトカメラ行列・視点・スライス割り当て、解像度、SceneContext、PSOを比較し、同じ場合はバッチ再構築・バッファ転送・深度クリア・影描画を省く。影ジョブと描画先への対応表は毎フレーム作り、ライト選択の変化を反映する。

入力はハッシュだけで判定せず実データを比較する。前のPSOを保持して、再読み込み時のアドレス再利用による誤判定も防ぐ。配列再生成、リソース解放、再利用条件の不一致、Nパスディザで配列を上書きした場合は失効する。

`StaticShadowCacheCompatible` をPipeline JSONへ追加した。既定はfalse、標準の `Object3D.ShadowMap.DepthOnly` はtrue。trueは「影が与えられたジオメトリ・マテリアル・ライトカメラ入力だけで決まる」という契約である。独自の時刻／手続き的な影シェーダーではfalseを維持する。

さらに、スキニング、影を落とすGPUパーティクル、テクスチャ指定、半透明マテリアルがある場合は再利用しない。標準の未指定テクスチャはエンジンの白テクスチャへ解決する。各フレームで一部の影だけを更新する方式ではなく、今回の実装は配列全体の保守的な再利用であり、影キャスターが1つ動けば再生成する。

## 描画リストの差分更新

Mesh／Spriteのキャッシュ済みエントリをその場で更新し、ソート済みキャッシュの一時コピーと文字列生成を削減した。最終描画リストの格納領域と文字列を保持し、前フレームと異なる出力位置だけを差し替える。エントリ数が減った場合は末尾を縮める。

動的値の監視は継続する。Transform、色、UV、テクスチャ、描画範囲、インスタンシング、テキスト装飾等を比較し、RenderOnlyシェイクやカメラ相対ピクセルスナップも毎フレーム反映する。構造・描画先・優先度・モデル版などの変更は既存のキャッシュ再構築経路を使う。テキスト・スキン・選択表示等の収集は毎フレーム行い、完全なイベント駆動化までは行っていない。`GetLastPatchedDrawEntryCount()` で最終リストの差し替え件数を確認できる。

## 最大配置の比較

16×16の全256セル、道路96・街灯80・その他施設80、浮遊光2046灯・マーカー4092枚。FHD描画／1280×720ウィンドウ、固定カメラ、影・ポストエフェクト有効、建築メニュー非表示。生産／イベント時計だけを隔離コピーで停止して所持数を固定した。改修前の実行ファイル＋旧シェーダーと、改修後の実行ファイル＋新シェーダーを前→後→後→前で独立起動した。

起動後9秒を除外し各約20秒を計測。FPSは完了フレーム数÷実時間。CPU区間は100msごとの採取でフレームIDを重複除去した平均であり、包含する区間を合算しない。ビルドと回帰テストは計測中に実行していない。
