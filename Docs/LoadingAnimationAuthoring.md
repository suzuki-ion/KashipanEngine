# シーンで作成する起動アニメーション

## 作成手順

1. Developmentのエディターで、ロード画面を編集する通常のシーンを開く。
2. メニューの「試験機能 → ロード画面の作成」を開く。
3. 「4区間のテンプレートをシーンに追加」を押す。追加はUndo/Redo可能。
4. `Loading Common`の子にある`Loading Sprite`のマテリアル、位置、大きさを変更する。必要なスプライトを追加する。
5. 各親の`LoadingAnimationSection`と`KeyFrameAnimator`を編集する。アニメーションは「自動再生」を有効にする。別オブジェクトを操作する場合は、各適用先の「対象」で選択するか、Hierarchyからドロップする。Noneは所有オブジェクトを表す。
6. 「現在のシーンを検証・プレビューへ反映」を押す。エラー、区間の長さ、長さの根拠となったアニメーションを確認する。
7. プレビューを再生する。全体、区間単体、共通のみを選べる。再生位置の秒数入力、一時停止、先頭への移動、読み込み完了時刻のシミュレーションが可能。
8. 「現在のシーンを書き出して起動時に使用」を押す。次回のRelease起動から使用する。編集用シーン自体は、通常のシーン保存で別途保存する。

テンプレートは共通スプライトのフェードイン、待機中の1秒360度EaseOutBack回転、フェードアウトを例として登録する。画像はアプリ側のマテリアルに差し替える。

## 区間

| 区間 | 表示・再生 |
|---|---|
| 開始 | 有効な区間なら1回再生。読み込みが先に完了しても、開始区間の終点まで再生する。 |
| 完了待ち | 読み込みが終わるまで区間を反復。完了時は即時移行、または現在の周期末まで待つ設定を選択できる。 |
| 終了 | 読み込み完了後に1回再生し、同じ起動ウィンドウを初回シーンへ引き継ぐ。 |
| 共通 | 開始から終了まで表示。共通側のアニメーションは全体の経過時間で再生する。 |

各区間の親に`LoadingAnimationSection`を1つ付け、その子孫に表示物を配置する。同じ区間のルートは1個とする。ネストした場合は最も近い区間マーカーに所属する。マーカー自体の`opacity_`は子孫全体の不透明度としてアニメーションできる。

区間外のスプライトは起動時の描画対象にしない。非表示のオブジェクトやコンポーネントも対象にしない。スプライト以外のオブジェクトは描画せず、階層のTransformは位置・回転・拡縮の計算に利用する。

## 終了位置とスキップ

- 「秒数を指定」では、正の有限秒数を使用する。0、負数、未指定、null、非数値、非有限値は、その区間をスキップする。
- 「最長アニメーションから自動」では、有効な適用先を持つ、自動再生するKeyFrameAnimatorのクリップから終了位置を算出する。再生速度と時間オフセットを考慮する。ループするクリップも1周期分を基準にする。
- 自動計算の候補がない、クリップの長さが0、実効秒数が0、同じ区間のルートが重複、といった場合も区間をスキップする。
- 他の区間までまとめて無効にせず、有効な区間だけ再生する。待機区間が無効でも読み込み完了は待つ。その間は共通オブジェクトだけを表示する。共通もなければ黒背景となる。
- 全区間が無効でも、カスタムパッケージが正常ならエンジン既定の演出へ置き換えず、読み込み完了後に引き継ぐ。

共通オブジェクトを各区間のアニメーションから操作できる。別の区間専用オブジェクトを操作する参照は検証対象となる。共通アニメーションと現在の区間が同じ値を書き換える場合は、現在の区間を優先する。終了した区間が共通オブジェクトに残した値は保持し、共通側でその値をアニメーションしている場合は共通の再生を続ける。

## 描画と対応範囲

- 1920×1080の論理座標。左下原点、+Yが上。TransformのZ回転はラジアン。ウィンドウサイズに応じて縦横比を維持して拡縮する。FHD環境では従来どおりHDのクライアントサイズを選ぶ。
- 描画はDirect2D。ハードウェア描画を要求し、利用できない場合はソフトウェア描画へフォールバックする。
- SpriteRendererの標準Object2D通常合成、Rect2D、アンカー、親子Transform、描画順、不透明度、色のOverride/Multiply、UV切り出しを扱う。画像はPNG/JPEG/BMP/TIFF。
- アニメーション対象はTransformのXY移動・XY拡縮・Z回転、SpriteRendererのRGBA・UV移動・UV拡縮、LoadingAnimationSectionの不透明度。
- 独自シェーダー、3D回転、独自メッシュ、UV回転、Add/Subtract色合成、スクリプト変数やその他のプロパティは起動用プレイヤーの対象外。対応しない指定は検証画面に表示する。一般のシーン実行側のKeyFrameAnimatorは従来のパラメータも引き続き利用できる。
- テキストコンポーネント、3D、音声、スクリプトなどは起動中に初期化しない。文字を出したい場合は文字を含む画像をSpriteRendererに使用する。
- エディターのプレビューとReleaseは同じコンパイラー・時間評価・Direct2D描画処理を使用する。通常のDX12シーン描画との全機能の見た目の一致を保証するものではない。

## 保存と起動

書き出し先はプロジェクト直下の`StartupAnimation/animation.json`と`StartupAnimation/images/`。キーフレームは埋め込み、必要な画像をコピーする。元のシーン、MaterialManager、TextureManagerを起動中に読み込む必要はない。JSONは最後に置き換え、画像は内容に基づく名前にして、書き出し途中で以前のパッケージの画像を上書きしない。

Releaseはプロジェクト決定後にこのパッケージを選択する。ウィンドウの最初の背景表示はプロジェクト選択より前に行う。未指定、壊れたパッケージ、画像の欠落・描画初期化失敗ではエンジン既定の演出へフォールバックする。区間の省略や無効秒数によるスキップは、パッケージ全体の破損として扱わない。

既定へ戻す場合は`StartupAnimation/animation.json`を移動する。Releaseのアセットコピーと配布、Development配布内の各プロジェクトにも任意の`StartupAnimation`を同梱する。Development自身の起動表示は従来のWebView2ログ画面のまま。

KeyFrameAnimatorの別オブジェクト参照はUUIDを保存し、適用時に同じシーンから解決する。対象の削除後は書き込みを行わない。部分木の複製・Prefabでは内部参照を複製後のUUIDへ置き換える。指定がない既存データは従来どおり所有オブジェクトを操作する。

この編集・書き出し機能はReleaseの起動再生に使用する。シーン切り替え中に通常のシーンとスクリプトを動かす方式は[ロード専用シーンの手順](SceneLoading.md)を参照。

## 検証

Developer PowerShellで`EngineTests/RunLoadingAnimationRegression.ps1`を実行すると、区間のスキップ、完了待ち、区間の優先順位、別オブジェクトへの適用、書き出しと再読み込み、Direct2Dの画像描画とリサイズを確認できる。

`EngineTests/RunStartupSplashRegression.ps1`は既定の描画・時間評価に加え、キャンセル、最小化、ウィンドウ引き継ぎ、カスタムデータの選択と無効区間のスキップを検証する。

Developmentビルド後の`EngineTests/RunLoadingAnimationBindingRegression.ps1`は、実際のSceneとKeyFrameAnimatorを使い、別オブジェクトへの適用、対象削除、部分木複製、外部参照の維持、明示した自分自身への参照の置き換えを確認する。
