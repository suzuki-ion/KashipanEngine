入力 (Input / InputCommand)

キーボード・マウス・コントローラーへの直接アクセスと、アクション名ベースで入力をマッピングする InputCommand システムを扱います。ゲームロジック（AngelScript）からは基本的に InputCommand 経由で入力を扱う設計です。

2つの入力アクセス方法

KashipanEngine の入力機能は大きく2層に分かれています。

  • デバイス直接アクセス（Keyboard / Mouse / Controller） … 特定のキーやボタンを直接判定する低レベルAPI。
  • アクションマッピング（InputCommand） … 「ジャンプ」「左移動」のようなアクション名に対して、キー・マウス・コントローラーの入力を1つ以上紐付けて評価する高レベルAPI。デバイスの種類を意識せずに入力を扱えるほか、シーンエディタや設定ファイルからの再割り当てにも対応しています。
推奨
ゲームロジック（AngelScriptスクリプトや InputCommandApplier コンポーネント）からは、キーやボタンを直接判定するのではなく InputCommand でアクション名を評価することを推奨します。キーコンフィグの変更やデバイスの追加に強くなります。

デバイスへの直接アクセス: Input

Input はキーボード・マウス・コントローラーそれぞれの入力デバイスクラスをまとめて保持するクラスです。GameEngine が内部で1つだけ生成し、SceneContext の GetInput() 経由でC++コード側から取得できます。

Input

Keyboard &GetKeyboard(); Mouse &GetMouse(); Controller &GetController();

それぞれ const 版のオーバーロードもあります。C++側のコンポーネントやツールコードから使う場合は、GetOwnerSceneContext()->GetInput()->GetKeyboard() のように取得します。

Keyboard

キー押下判定

bool IsDown(Key key) const; // 押されている bool IsTrigger(Key key) const; // 押された瞬間 bool IsRelease(Key key) const; // 離された瞬間 bool WasDown(Key key) const; // 前フレームで押されていたか

Key（Input/Key.h）はアルファベット・数字・矢印キー・修飾キー（左右個別 / 総称の両方）・Space / Enter / Escape / Tab / Backspace・ファンクションキー（F1～F12）を持つ列挙型です。

Mouse

ボタン判定

bool IsButtonDown(int button) const; bool IsButtonTrigger(int button) const; bool IsButtonRelease(int button) const; bool WasButtonDown(int button) const;

ボタン番号は Input/MouseButton.h の MouseButton（Left / Right / Middle / Button4～Button8）を int にキャストして渡します。

移動量・ホイール

int GetDeltaX() const; int GetDeltaY() const; // フレーム移動量 int GetWheel() const; // ホイールのフレーム差分 int GetWheelValue() const; // ホイールの累積値 int GetPrevDeltaX() const; int GetPrevDeltaY() const; int GetPrevWheel() const; int GetPrevWheelValue() const;

座標取得

POINT GetPos(HWND hwnd) const; POINT GetPos(const Window* window) const; int GetX(HWND hwnd) const; int GetY(HWND hwnd) const; int GetX(const Window* window) const; int GetY(const Window* window) const; // 各座標系にPrev版（前フレームの座標）も存在する

ウィンドウのクライアント座標系で取得します。HWND または Window ポインタのどちらでも指定できます。

Controller

接続状態とボタン

int GetPadCount() const noexcept; bool IsConnected(int index) const; bool WasConnected(int index) const; bool IsButtonDown(ControllerButton button, int index) const; bool IsButtonTrigger(ControllerButton button, int index) const; bool IsButtonRelease(ControllerButton button, int index) const; bool WasButtonDown(ControllerButton button, int index) const;

ControllerButton（Input/ControllerButton.h）は XInput 互換のビットマスク値で、十字キー・Start / Back・スティック押し込み・ショルダーボタン・A/B/X/Y を持ちます。index はコントローラー番号（0起点、複数台対応）です。

アナログ入力（トリガー・スティック）

int GetLeftTrigger(int index) const; int GetRightTrigger(int index) const; // 0～255 int GetLeftStickX(int index) const; int GetLeftStickY(int index) const; // -32767～32767 int GetRightStickX(int index) const; int GetRightStickY(int index) const; // 各値には Prev版（前フレーム）／Delta版（フレーム差分）も存在する

振動

void SetVibration(int index, int leftMotor, int rightMotor); // 各モーター強さ 0～65535 void StopVibration(int index);

入力デバイス判定

最後に入力があったデバイス

enum class InputDeviceType { KeyboardMouse, Controller }; InputDeviceType GetActiveDevice() const noexcept; bool IsUsingKeyboardMouse() const noexcept; bool IsUsingController() const noexcept; bool IsActiveDeviceChanged() const noexcept; // このフレームで切り替わったか int GetActiveControllerIndex() const noexcept; // 最後に操作されたコントローラー番号（未操作なら -1）

Input::Update() の最後に各デバイスの入力を調べ、最後に入力があったデバイスを記録します。どのデバイスにも入力がないフレームでは直前の判定を維持し、起動直後は KeyboardMouse です。ボタンの操作説明表示（キーボード用／コントローラー用の切り替え）などに利用できます。

  • キーボード: いずれかのキーが押された瞬間（Key に未対応のキーも含む）
  • マウス: ボタンが押された瞬間、ホイール操作、または一連の移動の累積量がしきい値以上になったとき（150ms 以上静止すると累積をリセット）
  • コントローラー: ボタンが押された瞬間、またはトリガー／スティックの入力量がしきい値以上のとき

同じフレームで両方に入力があった場合は現在のデバイスを維持します。コントローラーがすべて切断されると KeyboardMouse に戻ります。このプロセスのウィンドウ（ゲーム・エディターいずれも）が前面にないときは判定しません。エディター操作中も判定は継続されます。

しきい値

void SetMouseMoveThreshold(float pixels) noexcept; // 既定 16px void SetControllerStickThreshold(float threshold) noexcept; // 0.0～1.0、既定 0.3 void SetControllerTriggerThreshold(float threshold) noexcept; // 0.0～1.0、既定 0.3 // 各値には Get版も存在する void ResetDeviceThresholds(); // EngineSettings.json の値へ戻す

マウスの小さな揺れやトリガーの軽い押し込みでデバイスが切り替わらないようにするための値です。値は次の順に決まり、後のものほど優先されます。

  1. EngineSettings.json の input セクション（プロジェクト全体の初期値。省略時は上記の既定値）
  2. シーンコンポーネント InputDeviceSettings（上書きを有効にした項目だけ、そのシーンで置き換える）
  3. C++／スクリプトからの Set～Threshold 呼び出し、およびエディターの「入力状態」ウィンドウでの調整
// EngineSettings.json
"input": {
    "mouseMoveThreshold": 16.0,
    "controllerStickThreshold": 0.3,
    "controllerTriggerThreshold": 0.3
}

シーンコンポーネントの破棄時（シーン切り替え・Playの停止・エディターでのシーン再読み込み）に Scene が ResetDeviceThresholds() を呼び、しきい値を一度 EngineSettings.json の値へ戻します。その後に読み込まれたシーンに InputDeviceSettings があれば、その上書きが適用されます。そのため、3. で変更した値は次のシーンやPlay停止後には持ち越されません。

アクションマッピング: InputCommand

InputCommand は「アクション名（std::string）」に対して1つ以上の入力バインディングを登録し、Evaluate() でまとめて評価するクラスです。GameEngine が内部で1つ生成し、GameEngine::Context::inputCommand（01_Overview.html 参照）や SceneContext::GetInputCommand() から取得できます。

入力状態 InputState

キー・マウスボタン・コントローラーボタンの登録では、判定タイミングを InputState で指定します。

値意味
InputState::Down押されている間、毎フレーム true
InputState::Trigger押された瞬間だけ true
InputState::Release離された瞬間だけ true

RegisterCommand の各オーバーロード

キーボード

void RegisterCommand(const std::string &action, Key key, InputState state, bool invertValue = false);

マウスボタン

void RegisterCommand(const std::string &action, MouseButton button, InputState state, bool invertValue = false);

マウス軸

void RegisterCommand(const std::string &action, MouseAxis axis, void *hwnd = nullptr, float threshold = 0.0f, bool invertValue = false);

MouseAxis は X / Y / DeltaX / DeltaY / Wheel / DeltaWheel を持ちます。hwnd を指定するとクライアント座標系（MouseSpace::Client）、nullptr のままだとスクリーン座標系（MouseSpace::Screen）として扱われます。threshold は軸の絶対値がこれを超えたときに Triggered() を true にする閾値です。

コントローラーボタン

void RegisterCommand(const std::string &action, ControllerButton button, InputState state, int controllerIndex = 0, bool invertValue = false);

コントローラーアナログ（絶対値・状態判定つき）

void RegisterCommand(const std::string &action, ControllerAnalog analog, InputState state, int controllerIndex = 0, float threshold = 0.0f, bool invertValue = false);

ControllerAnalog は LeftTrigger / RightTrigger / LeftStickX / LeftStickY / RightStickX / RightStickY を持ちます。トリガーは 0.0f～1.0f、スティックは -1.0f～1.0f に正規化された値で評価されます。

コントローラーアナログ差分

void RegisterCommand(const std::string &action, ControllerAnalog analog, int controllerIndex = 0, float threshold = 0.0f, bool invertValue = false);

current - previous の差分を評価するオーバーロードです（InputState を取らない点で上のオーバーロードと区別されます）。

すべてのオーバーロードに共通する invertValue は、評価結果の Value() の符号を反転させます（例: 左移動用に登録したキーの値を負数として扱いたい場合など）。

評価: Evaluate と ReturnInfo

InputCommand::Evaluate

ReturnInfo Evaluate(const std::string &action) const; struct ReturnInfo { bool Triggered() const noexcept; float Value() const noexcept; };

Triggered() は登録したバインディングのいずれかが条件を満たしたか、Value() はその評価値（ボタン系は 0.0f/1.0f、軸系は連続値）です。同じアクション名に複数のバインディングを登録した場合はまとめて評価されます。

登録の保存・読み込み

JSON I/O

static constexpr const char* kDefaultSaveFilePath = "Assets/InputCommand.json"; bool SaveToJSON(const std::string &filepath) const; bool LoadFromJSON(const std::string &filepath); // 読み込み前に既存コマンドはクリアされる void Clear();

エンジンは起動時に kDefaultSaveFilePath（Assets/InputCommand.json）から自動的に LoadFromJSON を行い、終了時に SaveToJSON で保存します。シーンエディタ上でのキーコンフィグ編集もこのファイルを介して永続化されます。

コード側からの登録例: AppInitialize

ゲーム側で追加のコマンドをコードから登録したい場合は、唯一のC++エントリポイントである Application/AppInitialize.h の AppInitialize() で context.inputCommand を使います。 

#pragma once
#include <KashipanEngine.h>

namespace KashipanEngine {
inline void AppInitialize(const GameEngine::Context &context) {
    // トリガー判定でジャンプアクションを登録
    context.inputCommand->RegisterCommand("PlayerJump", Key::Space, InputCommand::InputState::Trigger);

    // 左右移動（Down判定、逆方向はinvertValueで符号反転）
    context.inputCommand->RegisterCommand("PlayerMoveLeft", Key::A, InputCommand::InputState::Down, /*invertValue=*/true);
    context.inputCommand->RegisterCommand("PlayerMoveRight", Key::D, InputCommand::InputState::Down);

    // コントローラーの左スティックXでも同じアクションへ追加登録できる
    context.inputCommand->RegisterCommand("PlayerMoveRight", InputCommand::ControllerAnalog::LeftStickX,
        InputCommand::InputState::Down, /*controllerIndex=*/0, /*threshold=*/0.2f);
}
}
ポイント
実運用では Assets/InputCommand.json とシーンエディタのキーコンフィグ画面で登録・編集するのが基本です。AppInitialize() でのコード登録は、デフォルト設定を保証したい場合や、JSONファイルが存在しない初回起動時のフォールバックとして使うと良いでしょう。

AngelScriptからの利用

AngelScriptスクリプト（Script/00_Index.html）からは、登録済みのアクション名を文字列で指定してグローバル関数から評価します。 

bool IsCommandTriggered(const string &in action);
float GetCommandValue(const string &in action);
void InputEvent() {
    if (IsCommandTriggered("PlayerJump")) {
        // ジャンプ処理
    }
    float moveDirection = 0.0f;
    if (IsCommandTriggered("PlayerMoveLeft")) {
        moveDirection = GetCommandValue("PlayerMoveLeft");
    }
}

内部的には SceneContext::GetInputCommand() で取得した InputCommand の Evaluate() をラップしているだけなので、C++側と同じバインディングをそのまま参照できます。詳しいスクリプトバインディングの一覧は Script/00_Index.html を参照してください。

入力デバイス判定とそのしきい値もグローバル関数から扱えます。スクリプトで変更したしきい値は、シーン切り替え・Playの停止時に EngineSettings.json／InputDeviceSettings の値へ戻ります。

InputDeviceType GetActiveInputDevice(); // InputDeviceType::KeyboardMouse / InputDeviceType::Controller
bool IsUsingKeyboardMouse();
bool IsUsingController();
bool IsInputDeviceChanged();
int GetActiveControllerIndex();

void SetMouseMoveThreshold(float pixels);
float GetMouseMoveThreshold();
void SetControllerStickThreshold(float threshold);
float GetControllerStickThreshold();
void SetControllerTriggerThreshold(float threshold);
float GetControllerTriggerThreshold();
void Update() {
    if (IsInputDeviceChanged()) {
        // 操作説明の表示をデバイスに合わせて切り替える
        SetGuideVisible(IsUsingController());
    }
}

コンポーネントから入力値を適用する: InputCommandApplier

スクリプトを書かずに、入力コマンドの評価結果を同じオブジェクトの他コンポーネントのパラメータへ直接反映させたい場合は InputCommandApplier コンポーネントが使えます（04_ObjectComponents.html のコンポーネント基礎も参照）。

InputCommandApplier final

bool WasApplied(const std::string &name) const; bool TryGetLastValue(const std::string &name, float &outValue) const; size_t GetCommandCount() const noexcept;

1つのコンポーネントに複数の「入力コマンド設定」（CommandEntry）を名前付きで登録できます（KeyFrameAnimatorのアニメーション登録と同様の構造）。各設定は評価するコマンド名・条件（ConditionType: CommandTrue/CommandFalse/ValueGreaterEqual/ValueLessEqual/ValueEqual）・値の種類（ValueSource: CommandValue/FixedValue）・Scale/Offset・複数のバインド先を持ち、毎フレーム条件を満たしたときだけ「値 × Scale + Offset」を ParameterBinding（KeyFrameAnimatorと共通の仕組み）で指定した適用先へ書き込みます。設定自体の追加・編集はInspectorから行い、スクリプトからは名前を指定して結果（WasApplied/TryGetLastValue）を参照します。
