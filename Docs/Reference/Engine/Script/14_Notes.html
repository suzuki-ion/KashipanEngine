リロード・エラー確認・注意事項

ScriptComponent::Reload() によるスクリプトの再コンパイルと、コンパイル/実行時エラーの確認方法、実装上ハマりやすい注意点をまとめます。

リロードとエラー確認

ScriptComponent::Reload() はスクリプトファイルを再コンパイルします。既にビルド済みの場合は内部で End() を呼んでから再構築するため、状態のクリーンアップは自動で行われます。[SerializeField] 付き変数の現在値はリロード後も維持されます。

シーンエディタでの実行時リロード
シーンエディタ（Editor/Architecture/01_Overview.html（シーンエディタ））上でスクリプトを編集して保存すると、多くの場合インスペクターから Reload() を呼ぶ導線が用意されています。コンパイルエラーがあった場合は再構築が失敗し、直前の状態（あるいは未ビルド状態）のまま残ります。 
ScriptComponent *script = obj->GetComponent<ScriptComponent>();
if (!script->Reload()) {
    // コンパイル/実行時エラーの内容を取得できる
    Log::Error(script->GetLastError());
}
エラーは静かに失敗する
Reload() が false を返しても例外は投げられません。スクリプトが動いていないように見える場合は、まず GetLastError()（内部的には直近のビルド失敗時のコンパイルメッセージ）を確認してください。よくある原因は、クラス名の変更後に ScriptComponentBehavior を実装したクラスが見つからない、[SerializeField] の型が非対応、array<T> をハンドル構文で宣言していない、といったものです。

EditorTool側にはホットリロード機構自体が無く、追加・変更はエディター再起動で反映されます（12_EditorToolScripting.html）。コンパイルエラーの詳細な調査には VS CodeによるAngelScriptデバッグ も活用できます。

注意事項

  • ハンドルの寿命: Object@ やコンポーネントのハンドルはエンジン側が所有する実体への参照（参照カウント無し）です。オブジェクトやコンポーネントが削除された後のハンドルへアクセスすると未定義動作になります。フレームをまたいで保持する場合は削除タイミングに注意してください（[SerializeField] の Object@ は IsValidObject() で安全確認できます。02_SerializeField.html）。
  • Behaviorクラスは1モジュール1つ: ScriptComponentBehavior を実装したクラスが複数ある場合、最初に見つかった1つだけが使用されます。
  • コライダーの追加/削除: 衝突コールバックのフックは毎フレームのコライダー数チェックで追従しますが、コライダーの追加とほぼ同時に発生した衝突は最初の1フレームだけ通知されないことがあります。
  • RayCollider / Ray2DCollider: レイキャスト専用のコライダーは常駐形状を持たないため、OnCollisionEnter 等の衝突イベントは発生しません。
  • 数学型は値型: Vector3 等を変数に代入するとコピーされます。Transform の座標を変更する場合は GetTranslate() で取得→変更→SetTranslate() で書き戻してください。
  • 文字列と数値の連結: "value=" + 1.0f のような連結が可能です（scriptstdstringアドオンによる）。
  • ポストプロセスエフェクトの内部Params構造体: BloomEffect等が内部で持つ Params 構造体自体はスクリプトへ公開されていません。フィールドごとのGet/Setメソッドを使用してください（07_ColliderAndPostEffect.html）。
  • Object@ を要求する引数: MeshRenderer::SetTargetObjectやCameraController::AddFollowTargetのように Object@ を引数に取るメソッドへ null を渡した場合は何もしません（クラッシュしません）。
  • AddComponentの追加数上限: コンポーネント種別ごとに1オブジェクトへ追加できる最大数が決まっており（例: Transformは1個まで）、上限を超えてAddComponentを呼ぶと失敗しfalseが返ります。
  • CloneObjectの複製範囲: Scene.CloneObjectは対象オブジェクト自身が持つコンポーネントのみを複製します。子オブジェクトの複製や、親子関係（Transformの親設定）の引き継ぎは行われません。
