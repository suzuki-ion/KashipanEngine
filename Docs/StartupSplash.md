# エンジン起動時のロゴ演出

Debug / Development / Release 共通。`--cook-assets` では表示しません。
エンジンルートの決定後、専用UIスレッドで通常のWin32ウィンドウを表示し、Direct2Dで描画します。
エンジン本体のDirectX12、WebView2、TextureManager、シーン、Loggerへの依存はありません。
初めにWin32で背景を表示し、その後にDirect2D・DirectWrite・WICの準備を進めます。
ハードウェア描画を優先し、利用できない場合はDirect2Dのソフトウェア描画に切り替えます。

## 演出

TD2_3 (`origin/TD2_3`、参照時 `13201337`) の
`Application/Scenes/EngineLogoScene.cpp` と3枚のPNGを元にしています。
素材は `EngineData/UI/Splash/engineLogo{Gear,Bread,Text}.png` です。
配置・アニメーションは **1920x1080の固定論理座標** で計算します。
元の2D投影に合わせて左下原点・Y上向き・正の回転は反時計回りとし、GDI+への描画時に
中心座標のYと回転符号だけを変換します。PNGや文字そのものは上下反転しません。

| 要素 | 1920x1080論理座標での設定 |
|---|---|
| 歯車・パンの中心 | (960,540) |
| 歯車・パンの最終サイズ | 512x512 |
| 文字ロゴ・帯の中心 | (960,216) |
| 文字ロゴ・帯の最大サイズ | 1024x256 |
| 帯の横移動 | X=448から1472へ |

元ブランチはウィンドウの高さ1280を参照する箇所がありましたが、本機能は指定された
1920x1080を基準に位置を再計算しています。そのため旧ウィンドウ全体の忠実な縮小ではありません。

描画領域は、カーソルのあるモニターの物理解像度の縦横それぞれ2/3を上限として、16:9で決定します。
タイトルバー・枠を含めて作業領域に収まるよう、必要な場合はさらに縮小します。
端数はピクセル単位で切り捨てます。

| モニター解像度 | 基本の描画領域（枠・作業領域による制限がない場合） |
|---|---|
| 1280x720 | 853x480 |
| 1920x1080 (FHD) | 1280x720 (HD) |
| 2560x1440 | 1706x960 |
| 3840x2160 (4K) | 2560x1440 |
| 1080x1920 (縦画面) | 720x405 |

実際の描画領域に対して `min(clientWidth/1920, clientHeight/1080)` の倍率を使い、
中心位置・サイズ・帯の移動量・読み込み文字を一括して拡縮します。縦横別々には伸ばしません。
回転角・演出時間は共通なので、解像度によってアニメーションの進行は変わりません。
例えばHDでは、歯車の中心(640,360)・サイズ約341.33、文字の中心(640,576)・サイズ約682.67x170.67になります
（この例の位置は左上原点の画面ピクセル座標）。

表示倍率の影響を二重に受けないよう、専用UIスレッドをPer-Monitor V2にし、
枠の大きさはウィンドウのDPIで計算します。描画バッファは実際のクライアントサイズで確保し、
最後の転送もピクセルサイズを明示します。異なるモニターへの移動完了、DPI変更、画面解像度変更時に
ウィンドウサイズを再計算します。

標準のタイトルバー・枠・最小化ボタン・閉じるボタンを備え、
タスクバーにも表示します。移動可能で、サイズ変更と最大化は無効です。最前面への固定は行いません。

閉じるボタンまたはAlt+F4で、演出を閉じてエンジンの起動を中止します。
読み込みやGPU処理を途中で強制終了することはせず、各初期化区間・ゲームループの安全な区切りで
中止を検出して後始末します。そのため、処理中の区間が終わるまで待つ場合があります。
通常の演出終了や内部の後始末は、ユーザーによる起動中止とは区別します。
最小化中も完了判定を進め、復元を待たずに演出を終了します。

- 0–1秒: 背景表示。
- 1–2秒: 歯車の拡大・回転、パンの拡大、帯による文字の出現。
- 2–3秒: 完成ロゴを保持。
- 3秒以降も読み込み中なら「読み込み中…」を表示。歯車は1秒で360度、EaseOutBackで繰り返し回転。
- 最初のシーンの構築後、そのシーンの最初の描画処理が復帰した時点で完了通知。
- 演出途中の完了は3秒まで待機。待機回転中の完了は現在の1回転を終えて停止。
- 1秒で黒へフェードしてウィンドウを閉じる。

フェード待機中はメインウィンドウのメッセージ処理を続け、ゲーム更新は進めません。
終了後にデルタ時間をリセットします。起動シーンの初期化と最初の更新・描画は
通知前に実行されるため、初期化時の音声等を遅延する機能ではありません。
`Startup.Total` は従来の読み込み・最初の描画までで、演出終了待ちは含めません。

素材不在・破損・ウィンドウ生成失敗時は演出を省略して起動を継続します。
起動失敗・終了時はRAIIで演出を中断し、UIスレッドを回収します。
配布処理は既存の `EngineData/UI/Splash` コピーを利用します。

## 検証

`EngineTests/SplashAnimationRegression.cpp` は通常のC++17以上で実行可能です。
早期完了、長時間待機、回転途中・回転境界での完了、タイマー遅延、フェードを検証します。
Visual Studioのx64開発者PowerShellで `EngineTests/RunStartupSplashRegression.ps1`
を実行すると、時刻ベースの検証と、実際の描画コードを使った独立ウィンドウの
早期完了・遅延完了・中断・素材不在・閉じる操作・最小化中の終了のライフサイクル検証を実行します。
標準ウィンドウのスタイルと、モニターに応じた描画領域も確認します。
`StartupSplashRenderingRegression.cpp` は実際の描画関数でHD/FHDの配置・帯・回転方向をピクセル検証し、
HDのロゴ完成時・読み込み待機時のPNGをGenerated配下へ保存します。
この独立検証ではエンジン起動やGPU描画は行いません。
シーン間のカスタムロード画面は、この起動専用機能の対象外です。

## 2026-10-28 の確認結果

- Development / Release x64 のエンジンビルド: 成功。
  Developmentは環境のPDB不一致を避けるため、Generated配下の一時propsでリンク時の
  デバッグ情報生成を無効化して検証。ReleaseはVisual Studio開発者環境を明示して成功。
  リポジトリのPDB設定は変更していません。ビルド後の全配布生成は省略しています。
- 時刻ベースの回帰テスト: 成功。
- 独立した実ウィンドウの回帰テスト: 早期完了、遅延完了、中断、素材不在が成功。
  早期完了は約4.16秒、4.20秒時点の完了通知は約6.13秒で終了、中断は約0.34秒で終了。
- 3枚のPNGが参照したTD2_3ブランチの素材とバイト単位で一致することを確認。
- エンジン・Hubの登録ソース/ヘッダの実在、Visual Studioフィルター整合性: 成功。
- 全体の配置テストは既存の生成済みQAプロジェクト7件に残る
  `SceneLoder.h` 参照で失敗。本機能と無関係な生成プロジェクトは変更していません。
- 画面確認ツールの初期化が失敗したため、見た目・動きの目視確認と実エンジン起動の
  通し確認は未実施。独立ウィンドウの検証はエンジン本体の実起動確認とは別です。

## 通常ウィンドウへの変更の確認

- タイトルバー・枠・システムメニュー・最小化ボタン・タスクバー表示を検証。
  サイズ変更・最大化・ツールウィンドウ・最前面固定の各スタイルが無効で、描画領域640x360を確認。
- 独立ウィンドウの6ケース（早期完了、遅延完了、内部中断、素材不在、ユーザーによる閉じる操作、
  最小化中の完了）が成功。通常の演出終了が起動中止扱いにならないことも検証。
- Development / Release x64 のビルド成功。環境由来のC1902を避けるため、検証用の子プロセスだけで
  `_CL_=/Z7` と `_LINK_=/DEBUG:NONE` を設定。リポジトリのデバッグ情報設定は変更していません。
- 隔離したEmptyテンプレートのRelease実エンジンでも、スプラッシュ表示直後と表示2.3秒後に
  閉じる要求を送り、両方で終了コード0を確認。測定プロセスの起動から終了までは約0.28秒と6.63秒。
  後者には閉じる要求までの2.3秒と、処理中の区間・後始末の待ち時間が含まれます。
- 上記はスタイル・ライフサイクル・終了動作の自動検証です。見た目・ドラッグ操作の目視確認は未実施です。

## 1920x1080基準・可変解像度への改修の確認

- Development / Release x64 のビルド成功（前節と同様の検証用PDB回避を使用）。
- 時刻ベースの回帰テストで、FHD→HD、4K→QHD、縦画面、作業領域の制限、縦横比維持、
  Y座標変換、回転符号、1920基準の帯の移動を確認。
- 実際の描画関数を使ったピクセル検証で、HD/FHD両方の歯車・文字・帯の位置と、
  非対称なスプライトの正の回転が反時計回りになることを確認。
- 実ウィンドウの6ケースがすべて成功。計測環境の描画領域が1280x720になることを確認。
- 同じ描画関数で生成した `Generated/StartupSplashRegression/HD-Logo.png` と
  `HD-Loading.png` を確認し、文字ロゴが歯車の下に配置されることと待機文字の配置を確認。
- 複数の物理モニター間のドラッグ、高DPI環境での実ウィンドウ操作は未検証。
  4K・縦画面等のサイズ計算の検証と、実ハードウェアでの検証は区別しています。

## Direct2Dへの移行

現在は画像・図形・フェードをDirect2D、文字をDirectWriteで描画します。
高精度の単調時計と待機可能タイマーを使用し、通常時は60FPSを目標とします。
画像とフォントは再利用し、画像は表示サイズに合わせて一度縮小してGPUへアップロードします。
描画先のリサイズ・再生成にも対応します。

冒頭の背景を表示してから描画リソースを準備し、準備が1秒を超える場合もロゴ演出の途中を飛ばしません。
描画方式は `SplashScreen::GetRenderingBackend()` で確認できます。

ビルド、機能検証、FPSと初期化時間の比較結果は
[StartupSplashDirect2DMigration.md](StartupSplashDirect2DMigration.md) を参照してください。
