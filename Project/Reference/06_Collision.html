コライダーと物理演算

KashipanEngine/Objects/Components/Collider/ の各種コライダーコンポーネントと、KashipanEngine/Objects/Collision/Collider.h にある衝突判定エンジンの薄いラッパーについてまとめます。3D判定は Externals/ReactPhysics3D を内部で利用し、2D判定は独自の幾何アルゴリズム（CollisionAlgorithms2D.h）で行われます。

ディレクトリ構成

Objects/
├── Collision/
│   ├── Collider.h / .cpp          … 衝突判定エンジンの実体（ReactPhysics3Dラッパー、2D/3D共通管理）
│   ├── CollisionAlgorithms2D.h    … 2D形状同士の交差判定アルゴリズム
│   └── CollisionAlgorithms3D.h    … 3D形状同士の交差判定アルゴリズム（一部の下位処理で使用）
└── Components/Collider/
    ├── ICollider.h                … 全コライダーコンポーネントの基底クラス
    ├── BoxCollider.h / SphereCollider.h / CapsuleCollider.h / MeshCollider.h / RayCollider.h   … 3D用
    ├── Box2DCollider.h / Circle2DCollider.h / Capsule2DCollider.h / Ray2DCollider.h            … 2D用
    └── RigidBody2D.h / RigidBody3D.h                                                            … 物理挙動
ポイント
「当たり判定の形状（BoxCollider等）」と「物理挙動（RigidBody2D/RigidBody3D）」は別コンポーネントです。RigidBody を付けずにコライダーだけを付ければ、物理的な押し戻しを行わない静的な当たり判定（トリガーやセンサー用途）として使えます。

衝突結果を受け取る構造体

低レベルのObjects/Collision/Collider.hにはHitInfoという最小限のフィールド（isHit / normal / penetration）を持つ構造体もありますが、実際にコンポーネントの衝突コールバックへ渡されるのは HitInfo2D / HitInfo3D です。

HitInfo2D / HitInfo3D

struct HitInfo2D { // HitInfo3Dも同じ構成 bool isHit = false; Vector3 normal{0.0f, 0.0f, 0.0f}; float penetration = 0.0f; EmptyObject *selfObject = nullptr; EmptyObject *otherObject = nullptr; ICollider *selfCollider = nullptr; ICollider *otherCollider = nullptr; };

selfObject/selfCollider がコールバックの持ち主側、otherObject/otherCollider が衝突相手側です。

形状情報 ColliderInfo3D の形状バリアント

using ShapeVariant = std::variant< SphereShape3D, // center, radius BoxShape3D, // center, halfExtents CapsuleShape3D, // center, radius, height ConvexMeshShape3D, // vertices, indices, scale ConcaveMeshShape3D, // vertices, indices, scale HeightFieldShape3D>; // heights, width, length, minHeight, maxHeight, scale

各コライダーコンポーネントの BuildColliderInfo3D()（または2D用の BuildColliderInfo2D()）が、Transformと自身のパラメータからこの形状情報を毎フレーム構築します。この情報は内部の SceneObjectCollider コンポーネントが収集し、Collider エンジンへ渡します。

ICollider — コライダー共通基底クラス

全てのコライダーコンポーネントは ICollider（Collision カテゴリ）を継承します。生成時（Initialize）にシーンの SceneObjectCollider コンポーネントへ自動登録され、以後は毎フレーム BuildColliderInfo2D/BuildColliderInfo3D が呼ばれて最新の形状が読み取られるため、パラメータを変更しても再登録は不要です。

ICollider::Shape

enum class Shape { Box, Sphere, Capsule, Ray, Mesh, // 3D Ray2D, Box2D, Circle2D, Capsule2D, // 2D };

トリガー・連続衝突判定（CCD）

Shape GetShape() const noexcept; bool Is2D() const noexcept; bool IsTrigger() const noexcept; void SetTrigger(bool isTrigger) noexcept; bool IsContinuousDetection() const noexcept; void SetContinuousDetection(bool enabled) noexcept;

SetContinuousDetection(true) にすると、前フレーム位置から現在位置までの移動経路を形状サイズ以下の刻みに分割して中間位置でも判定します。高速に動く弾丸など、通常判定ではすり抜けてしまうオブジェクトに使用します。

衝突コールバック（3D用 / 2D用）

void SetOnCollisionEnter3D(std::function<void(const HitInfo3D &)> callback); void SetOnCollisionStay3D(std::function<void(const HitInfo3D &)> callback); void SetOnCollisionExit3D(std::function<void(const HitInfo3D &)> callback); void SetOnCollisionEnter2D(std::function<void(const HitInfo2D &)> callback); void SetOnCollisionStay2D(std::function<void(const HitInfo2D &)> callback); void SetOnCollisionExit2D(std::function<void(const HitInfo2D &)> callback);

Transform同期設定

bool IsSyncPositionEnabled(int axis) const noexcept; bool IsSyncRotationEnabled(int axis) const noexcept; bool IsSyncScaleEnabled(int axis) const noexcept; Vector3 GetSyncedOwnerPosition() const; Vector3 GetSyncedOwnerRotationEuler() const; Vector3 GetSyncedOwnerScale() const;

位置・回転・スケールをそれぞれXYZ軸ごとに、同オブジェクトの Transform へ追従させるかを個別に選択できます。無効にした軸は形状計算上「値なし」（位置・回転は0、スケールは1）として扱われます。位置・回転は既定で全軸追従、スケールは既存挙動を変えないため既定で非追従です。

BoxCollider

void SetSize(const Vector3 &size); // 既定 (1,1,1) void SetCenter(const Vector3 &center); // ローカルオフセット

SphereCollider

void SetRadius(float radius); // 既定 0.5 void SetCenter(const Vector3 &center);

CapsuleCollider

void SetRadius(float radius); // 既定 0.5 void SetHeight(float height); // 既定 1.0 void SetCenter(const Vector3 &center);

MeshCollider

void SetConvex(bool convex) noexcept; // 既定 true bool IsConvex() const noexcept; void SetMeshHandle(ModelManager::ModelHandle handle) noexcept; // 未指定ならMeshFilterのメッシュを使用 ModelManager::ModelHandle GetEffectiveMeshHandle() const;

UnityのMeshColliderに相当します。Convexを有効にした場合のみ凸包として扱われ、他のMeshCollider同士でも衝突できます（物理エンジン側の制約により、非Convexなメッシュ同士の衝突判定には対応していません）。メッシュを明示的に指定しない場合は、同オブジェクトの MeshFilter（05_Rendering.html 参照）のメッシュをそのまま使います。

RayCollider

void SetDirection(const Vector3 &direction); // 既定 (0,-1,0) void SetMaxDistance(float maxDistance); // 既定 10.0 bool CastRay(HitInfo3D &outHit) const;

常駐する当たり判定形状を持たないため、OnCollisionEnter等のコールバックは呼ばれません。代わりに CastRay() を呼び出したタイミングでシーンの物理ワールドへレイキャストを行い、結果を直接受け取ります。

Ray2DCollider

オーナーオブジェクトのワールド座標を始点とし、指定した方向・長さの線分として扱われます。3DのRayColliderと異なり明示的なCastRay()は持たず、常駐する線分形状として他のコライダーとの衝突コールバックの対象になります。

RigidBody3D / RigidBody2D — 物理挙動

コライダーが「形状」を表すのに対し、RigidBodyは「物理的な動き（質量・重力・速度）」を表すコンポーネントです。同一オブジェクトに複数のコライダーが付いている場合、どのコライダーの形状を物理ボディに使うかを SetSelectedCollider() で選べます（未選択の場合はどれでも使用可）。

RigidBody3D（ReactPhysics3DのRigidBodyを内部で保持）

void SetBodyType(reactphysics3d::BodyType type); // Static / Kinematic / Dynamic void SetMass(float mass); // 既定 1.0 void SetUseGravity(bool enabled); // 既定 true void SetInterpolate(bool enabled); // 既定 true reactphysics3d::RigidBody *GetRigidBody() const; void SetSelectedCollider(ICollider *collider); ICollider *GetSelectedCollider() const; void SyncFromTransform();

SyncFromTransform() は現在のTransformの位置・回転を物理ボディへ即座に反映します。エディタでオブジェクトを移動させても生成済みの物理ボディは自動追従しないため、Play開始時にこれを呼んで同期を取る必要があります。物理ボディの位置・回転は毎フレーム Update() で Transform 側へ書き戻されます。

RigidBody2D（独自の簡易2D物理パラメータ）

void SetVelocity(const Vector2 &velocity); const Vector2 &GetVelocity() const noexcept; void SetMass(float mass); // 既定 1.0 void SetUseGravity(bool enabled); // 既定 true void SetSelectedCollider(ICollider *collider);

衝突コールバックの仕組み

C++側では ICollider::SetOnCollisionEnter3D() 等に std::function<void(const HitInfo3D &)> を渡すことでコールバックを登録できます。isTriggerを有効にしたコライダーは物理的な押し戻し（衝突応答）を行わず、コールバック通知のみが行われます。

AngelScriptからの利用
ゲームロジックは通常C++ではなくScriptComponent（07_Scripting.html 参照）で書きます。スクリプト側で ScriptComponentBehavior に以下のメソッドを実装すると、同一オブジェクトのコライダーの衝突イベントに応じて自動的に呼び出されます。 
void OnCollisionEnter(const HitInfo &in) { /* 衝突開始時 */ }
void OnCollisionStay(const HitInfo &in)  { /* 衝突継続中、毎フレーム */ }
void OnCollisionExit(const HitInfo &in)  { /* 衝突終了時 */ }
スクリプト側の HitInfo は normal / penetration / selfObject / otherObject / selfCollider / otherCollider を持ち、C++側の HitInfo2D/HitInfo3Dを1つの型としてAngelScriptへ橋渡ししたものです。ScriptComponentは内部でIColliderの各コールバックをフックしてこれを実現しています。

トリガーと衝突フィルタ

IsTrigger()/SetTrigger()で、物理的な押し戻しを行わない「センサー」的なコライダーとして扱うかを切り替えられます。トリガーを有効にしてもOnCollisionEnter/Stay/Exit系のコールバックは通常どおり発火します。

実装メモ: 属性ベースの衝突フィルタ
低レベルの ColliderInfo2D/ColliderInfo3D にはattribute/ignoreAttributeというstd::bitset<32>のペアがあり、Collider.cpp内部の判定処理（ShouldTest）はこれを使ってペアごとに判定をスキップするレイヤーマスク的な仕組みを持っています。ただし現時点ではIColliderおよびその派生クラスにこれを設定する公開APIは無く、内部的な拡張ポイントに留まっています。レイヤー的な衝突フィルタが必要な場合は、コールバック内でotherObjectのタグ（03_GameObjects.htmlのTag参照）等を見て判定するのが現状の方法です。
