ポストエフェクト

KashipanEngine/Objects/Components/PostProcessing/ 配下の各種ポストエフェクトコンポーネントについて解説します。いずれも ScreenBufferObject（11_Window.html 参照）が付与されたオブジェクトへ追加コンポーネントとして付けることで、そのオフスクリーンバッファに対して効果を適用します。

仕組み — IPostProcessComponent

全てのポストエフェクトは IPostProcessComponent（Objects/Components/PostProcessing/IPostProcessComponent.h）を基底クラスに持つ IObjectComponent です。COMPONENT_CATEGORY("PostProcessing") により全派生クラスが同じカテゴリへ分類されますが、各エフェクトはそれぞれ個別のコンポーネント型（GetComponentTypeID<派生型>()）として登録されるため、1つのオブジェクトへ複数のポストエフェクトを重ねて付与できます。

付与先の前提
ポストエフェクトは同一オブジェクトの ScreenBufferObject コンポーネントが持つ ScreenBuffer に対して適用されます。ScreenBufferObject が無いオブジェクトへ付けても効果は発生しません。詳しくは 11_Window.html を参照してください。

2つの実装方式

派生クラスは次のいずれかの方式でエフェクトの中身を実装します。

  • 宣言的パス定義（BuildPasses()） — 1回のフルスクリーンパスで完結する単純なエフェクト向け。使用するパイプライン名と、定数バッファ・テクスチャ・サンプラーのバインド要求（PassInfo）を返すだけで、実際の描画コマンド発行は Renderer 側が行います。BoxFilterEffect、ChromaticAberrationEffect、ColorAdjustEffect、DissolveEffect、DitherEffect、DotMatrixEffect、FXAAEffect、GaussianFilterEffect、GrayscaleEffect、OutlineEffect、RadialBlurEffect、VignetteEffect がこの方式です。
  • カスタム描画（RenderCustom()） — 中間レンダーターゲットを使う多段パスが必要なエフェクト向け。screenBuffer->NextPass() で読み取り面を確定させてから内部レンダーターゲットへ複数回描画し、最後に screenBuffer->RebindWriteTarget() で書き込み面へ戻して合成します。BloomEffect、AmbientOcclusionEffect、DepthOfFieldEffect、MotionBlurEffect がこの方式です。

カメラ情報の自動注入

深度からワールド座標を再構成する（AO）、Near/Farで深度を線形化する（Outline/DoF/MotionBlur）といった処理には、実際にそのスクリーンバッファへ描画したカメラの情報が必要です。Renderer は毎フレーム、該当カメラを解決して CameraInfo（viewProjection / worldPosition / nearClip / farClip）を SetCameraInfoInterface(Passkey<Renderer>, ...) 経由で注入します。派生クラスは保護メンバの GetCameraInfo() でこれを参照でき、ユーザー側でNear/Far等を別途指定する必要はありません。カメラが解決できなかった場合は CameraInfo::valid が false になり、該当エフェクトはその項では描画をスキップします。

適用先の除外設定 USE_IMGUI

同一オブジェクトに ScreenBufferObject が2つ以上ある場合、各ポストエフェクトコンポーネントは IsScreenBufferIncluded() / 内部の excludedScreenBufferNames_ によって、どの ScreenBuffer へ適用するかを個別に除外設定できます（エディター上では "Apply Target Filter" のチェックボックスとして表示されます）。

詳細: BloomEffect

BloomEffect final

struct Params { float threshold = 1.0f; float softKnee = 0.5f; float intensity = 0.8f; float blurRadius = 1.0f; std::uint32_t iterations = 4; // ダウンサンプル段数 (1..16) }; void SetParams(const Params &params); const Params &GetParams() const noexcept;

Prefilter → Blur → Downsample/Blur チェーン → Upsample累積 → Composite、という多段パスで実装されており、iterations で指定した段数分の縮小ピラミッド（RenderTargetResource + ShaderResourceResource）をオーナーの ScreenBuffer のサイズ・フォーマットに合わせて内部で確保します。threshold/softKnee で抽出する明部のしきい値を、intensity/blurRadius で最終的な強さとぼかし量を調整します。

詳細: OutlineEffect

OutlineEffect final

struct Params { float threshold = 0.1f; float thickness = 1.0f; float color[4] = { 1.0f, 1.0f, 1.0f, 1.0f }; }; void SetParams(const Params &params); const Params &GetParams() const noexcept;

単一パスの宣言的エフェクトで、深度テクスチャ（gDepthTexture）とカメラの Near/Far（GetCameraInfo() から自動解決）をシェーダーへ渡し、深度差から輪郭を検出して color で塗ります。カメラが未解決の場合は深度の線形化が不正確になる可能性がある旨がエディター上に警告表示されます。

使用例

実運用では シーンエディタ の Add Component メニューから付与するのが基本ですが、コードから直接組み立てる場合は次のようになります。 

#include <KashipanEngine.h>
using namespace KashipanEngine;

// screenBufferObj は既に AddComponent<ScreenBufferObject>() 済みのオブジェクト
auto *bloom = obj->AddComponent<BloomEffect>();
BloomEffect::Params bloomParams;
bloomParams.threshold = 1.2f;
bloomParams.intensity = 1.0f;
bloom->SetParams(bloomParams);

auto *outline = obj->AddComponent<OutlineEffect>();
OutlineEffect::Params outlineParams;
outlineParams.thickness = 2.0f;
outlineParams.color[0] = 0.0f; outlineParams.color[1] = 0.0f;
outlineParams.color[2] = 0.0f; outlineParams.color[3] = 1.0f;
outline->SetParams(outlineParams);

複数のポストエフェクトを同一オブジェクトへ追加した場合、コンポーネントの追加順（あるいはシーンエディタでの並び順）にパスが適用されます。
