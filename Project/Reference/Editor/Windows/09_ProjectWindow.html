Project

1本のゲームを構成するアセット・シーン・設定をひとまとめにした単位がプロジェクトです。プロジェクトの選択は、エディターとは別のプロジェクトランチャー（KashipanHub.exe）か、エディター内の File›Project... で開くProjectウィンドウから行います。

プロジェクトとは

プロジェクトはエンジンルート直下のProjects/<プロジェクト名>/フォルダそのものです。ゲーム1本分のデータがこのフォルダに閉じているため、別のゲームを作りたくなったらフォルダごと新しく生やせばよく、既存のアセットを手作業で消して回る必要はありません。

Project.jsonを持つフォルダがプロジェクトとして認識されます。

プロジェクトフォルダの構成

場所内容
Project.jsonプロジェクト定義ファイル。このファイルの有無がプロジェクトかどうかの判定基準になる
Assets/ゲームが使うすべてのアセット。実行時のAssetsルートはここを指す
Assets/SceneList.json登録シーンの一覧と起動シーン（Scene Listで編集）
Assets/InputCommand.json入力アクションの定義（Input Command Editorで編集）
Assets/KashipanEngine/エンジンの既定リソース（フォント・翻訳・パイプライン設定・エンジンロゴなど）
EditorSettings.jsonこのプロジェクトでのエディターUIの状態（ツリーの開閉、ウィンドウの表示/非表示など）
SceneBackups/自動バックアップされたシーン（Auto Save Settingsで設定）
Screenshots/ScreenBufferObjectが書き出すスクリーンショットの既定の保存先
as.predefinedVSCodeのAngelScript Language Server用の型定義（エンジン起動時に自動生成）
SceneList.jsonとInputCommand.jsonがAssets/直下にある理由
これらはエンジンが用意する既定リソースではなく「このゲームが定義するデータ」です。同じ理由から、EditorSettings.jsonはAssets/の外（プロジェクトルート直下）に置かれます。配布時にAssets/をそのままコピーしても、エディターの作業状態が製品に混入しません。

エンジンルート側の構成

プロジェクトの外側、つまりエンジン自体に属するものは次の場所にあります。

場所内容
Projects/すべてのプロジェクトが並ぶフォルダ
AssetsTemplate/新規プロジェクト作成時にAssets/へコピーされるひな形
UserSettings.jsonプロジェクトをまたいで共有される個人設定（配色・フォント・表示倍率・前回開いたプロジェクト）
EditorTools/エンジン共通のエディター拡張スクリプト（.as）
EngineRoot.txtexeと同じフォルダに置かれ、エンジンルートの位置を指すマーカー（ビルド時に自動生成）
Logs/ / Dumps/実行ログとクラッシュダンプ

プロジェクトランチャー

エディター本体（KashipanEngine.exe）と同じフォルダにある KashipanHub.exe が、プロジェクトを選んでエディターを起動するためのランチャーです。DirectXやImGuiを使わないので、GPUの初期化を待たずに一瞬で開きます。

画面はWebView2でHTMLとして描画しており、配色はこのリファレンスと同じ定義を使っているため、OSのライト／ダーク設定にも追従します。UIの実体は Launcher/UI/ 配下の index.html・launcher.css・launcher.js で、見た目を調整したい場合はこれらを編集するだけで反映されます（再ビルドは不要）。

項目内容
プロジェクト一覧Projects/配下のプロジェクト。前回開いたプロジェクトが最初から選択された状態になる。項目のダブルクリックはそのまま「開く」として扱われる
開く選択中のプロジェクトでエディターを起動し、ランチャー自身は閉じる
更新Projects/を再スキャンする
新規プロジェクト名 / 作成AssetsTemplate/から新しいプロジェクトを作る。作成しただけでは開かないので、続けて開くを押す
ランチャーは配布物には含めません
ランチャーはプロジェクトを切り替えるためのエディター用ツールです。ゲームを配布する際はKashipanEngine.exeとその隣のAssets/だけを配置します。
WebView2ランタイムが無い環境では
描画には別途OSにインストールされたWebView2ランタイムが使われます（Windows 11には標準で同梱）。ランタイムが無い場合や Launcher/UI/ が見つからない場合は、Win32コントロールで組んだ簡素な画面へ自動的に切り替わるため、ランチャーが起動できなくなることはありません。できることは同じです。

コマンドラインでプロジェクトを指定する

ランチャーは選ばれたプロジェクトを、次の形でエディターへ引き渡しているだけです。同じ指定は手動やスクリプトからも使えます。

KashipanEngine.exe --project <プロジェクト名 または プロジェクトフォルダの絶対パス>

開くプロジェクトは--projectの指定 → UserSettings.jsonに記録された前回のプロジェクト → Projects/配下で最初に見つかったプロジェクト、の順に決まります。指定されたプロジェクトが見つからない場合は警告をログへ出したうえで、以降の順序へフォールバックします。

Project ウィンドウ

File›Project...で表示を切り替えます。ランチャーを経由せず、作業中のエディターからそのままプロジェクトを切り替えたり新規作成したりできます。表示状態はEditorSettings.jsonに保存されます。

Current Project

現在開いているプロジェクトの名前とフォルダのフルパスが表示されます。切り替えを実行した直後は、開き直そうとしているプロジェクト名がここに表示されます。

Projects

Projects/配下で見つかったプロジェクトの一覧です。

項目内容
RefreshProjects/を再スキャンする。エディターの外でプロジェクトを追加した場合に使う
Openエディターを閉じ、そのプロジェクトを開いた状態で起動し直す。現在開いているプロジェクトの行ではOpen (current)と表示され、無効化される
切り替えるとエディターが起動し直します
エンジンは起動時にテクスチャ・モデル・音声などをGPUリソースごと読み込むため、実行中にプロジェクトを丸ごと差し替えることはできません。Openを押すとエディターは通常どおり終了処理（シーンの自動保存など）を行ったうえで自分自身を閉じ、選んだプロジェクトを開いた状態で自動的に起動し直します。

New Project

名前を入力してCreateを押すと、Projects/<名前>/が作られ、AssetsTemplate/の中身がそのAssets/へコピーされます。作成しただけでは開いているプロジェクトは変わらないため、切り替えたい場合は続けて一覧のOpenを押します。

名前はフォルダ名としてそのまま使われるため、次の場合は作成できません（理由がウィンドウ内に表示されます）。

  • 空文字の場合
  • \ / : * ? " < > | を含む場合
  • 先頭または末尾が空白、あるいは末尾がピリオドの場合（Windowsが自動的に取り除いてしまうため）
  • 同名のフォルダが既に存在する場合
プロジェクトが1つも無い場合
初回起動時などProjects/に有効なプロジェクトが1つも無い場合は、エンジンがNewProjectという名前のプロジェクトをAssetsTemplate/から自動生成して開きます。

アセットのパス表記

プロジェクトが分かれても、シーンJSONやマテリアル、ScriptComponentのScript Pathに保存されるパスはAssets/Application/Model/Player.objのようなプロジェクトルートからの相対パスのままです。実際のファイルを開く直前にProjects/<名前>/Assets/...へ変換されるため、プロジェクトの置き場所が変わっても、別のプロジェクトへアセットをコピーしても、保存された値はそのまま通用します。

Assets Windowのフォルダツリーやツールチップに出るパスも同じ表記です。

ゲームを配布するとき

配布用のexeは、Projects/の中を見るのではなくexeと同じ階層に置かれたAssets/フォルダを使います。プロジェクトのAssets/をexeの隣にコピーすれば動作します。

この状態ではプロジェクトの選択・作成は行われず、Projectウィンドウにもその旨だけが表示されます。EditorSettings.json・SceneBackups/・as.predefinedはいずれもAssets/の外にあるため、コピー対象に含まれません。
