エンジン概要とアーキテクチャ

KashipanEngine 全体のディレクトリ構成、起動フロー、設計思想（コンポジション・final・Passkey）をまとめます。他のページを読む前に一度目を通しておくと理解が早くなります。

ポイント
エンジン本体（KashipanEngine/）とゲーム側（Application/, Assets/）は明確に分離されています。ゲーム側のC++コードは実質 AppInitialize.h 1ファイルのみで、実際のゲームコンテンツは シーンJSON と AngelScriptファイル に置かれます。

唯一の公開ヘッダ

エンジンを利用する側は基本的に KashipanEngine.h をインクルードするだけで全モジュールにアクセスできます。

#include <KashipanEngine.h>

using namespace KashipanEngine;

起動フローと GameEngine

エンジンの実行主体は Core/GameEngine.h の GameEngine クラスです。main() 相当の処理はエンジン内部に隠蔽されており、ゲーム側が直接生成することはできません（コンストラクタが専用の Passkey を要求します）。ゲーム側が触れるのは起動時に渡ってくる GameEngine::Context だけです。

GameEngine::Context

struct Context { SceneManager *sceneManager = nullptr; InputCommand *inputCommand = nullptr; void SetGameLoopEndCondition(const std::function<bool()> &func) const; };

Context は AppInitialize() の引数として渡され、シーンの登録や入力コマンドの登録、ゲームループの終了条件のカスタマイズに使います。

GameEngine 静的メソッド

static void GameEngine::RequestExitGameLoop() noexcept; static bool GameEngine::IsExitGameLoopRequested() noexcept;

任意の場所からゲームループの終了をリクエストできます。

アプリ側エントリポイント: AppInitialize

ゲーム側で唯一実装するC++関数が Application/AppInitialize.h の AppInitialize() です。

#pragma once
#include <KashipanEngine.h>

namespace KashipanEngine {
inline void AppInitialize(const GameEngine::Context &context) {
    // シーンの登録は Assets/KashipanEngine/SceneList.json とシーンエディタで行うのが基本。
    // コードから追加登録したい場合は以下のようにする。
    // context.sceneManager->RegisterSceneFile("Title", "Assets/Scenes/Title/Title.scene");

    // 入力コマンドの登録もここで行える（詳細は 08_Input.html 参照）。
    // context.inputCommand->RegisterCommand("PlayerJump", Key::Space, InputState::Trigger);
}
}

詳しくは 02_Scenes.html・08_Input.html を参照してください。

設計思想

継承よりコンポジション

EmptyObject、Scene、MeshRenderer、Transform など、エンジンの主要クラスのほとんどが final 指定されています。つまり、ゲーム側で独自のオブジェクト型やシーン型を作るために継承する、という設計にはなっていません。代わりに、既存のオブジェクトへ用途別のコンポーネントを AddComponent<T>() で組み合わせていく Unity 的なコンポジション方式を採用しています。

注意
「シーンやオブジェクトをC++で継承して独自クラスを作る」という発想はこのエンジンには通用しません。振る舞いを追加したい場合はコンポーネントを追加するか、AngelScriptスクリプトを書きます。

Passkeyイディオムによるアクセス制御

Utilities/Passkeys.h で定義される Passkey<T> は、「特定のクラス T からしか呼び出せない public メソッド」を型安全に実現するイディオムです。例えば EmptyObject::SaveToJson(Passkey<Scene>) は Scene クラスの内部からしか呼び出せません。ヘッダを読んでいて引数に見慣れない Passkey<...> 型が出てきたら、「このメソッドは特定の内部クラス専用で、ゲーム側からは通常呼ばない」という合図だと理解してください。

JSONによるデータ駆動

シーン・オブジェクト・コンポーネントはすべて SaveToJson() / LoadFromJson() の対で nlohmann::json（エンジン内では JSON 型エイリアス）へシリアライズできる一貫した設計です。シーンエディタでの編集内容はそのままこの仕組みでファイルに保存されます。パイプライン定義（Assets/KashipanEngine/ 配下）などエンジンの各種設定もJSONで記述します。

ビルド構成とImGui

DEBUG_BUILD / DEVELOPMENT_BUILD / RELEASE_BUILD のビルドマクロと、シーンエディタ等のツール群を有効化する USE_IMGUI マクロがあります。多くのクラスに #if defined(USE_IMGUI) のブロックがあり、エディタ機能はこのマクロの有無で切り替わります。詳細は 14_BuildMacros.html を参照してください。
