ゲームオブジェクト (EmptyObject)

KashipanEngine には「ゲームオブジェクト型」が1種類しかありません。EmptyObject というただの空の入れ物に、コンポーネントを組み合わせて機能を持たせていきます。ここでは EmptyObject 自体のAPIと、コンポジションという考え方を説明します。

EmptyObject クラス final

Objects/EmptyObject.h に定義されています。Scene と同じく final 指定されており、継承して class Enemy : public EmptyObject のような独自オブジェクト型を作ることはできません。「敵らしさ」や「プレイヤーらしさ」は、後述のオブジェクトコンポーネントの組み合わせによって表現します。

コンストラクタは Passkey<Scene> を要求するため、ゲーム側から直接 new EmptyObject(...) することはできません。オブジェクトの生成は必ず Scene::CreateEmptyObject()（またはシーンコンポーネントからは SceneContext::CreateEmptyObject()）を経由します。

基本情報

std::unique_ptr<EmptyObject> Clone() const; void SetName(const std::string &name); const std::string &GetName() const; void SetTag(const std::string &tagName); const Tag &GetTag() const noexcept; const std::string &GetTagName() const noexcept; void SetObjectID(const UUID128 &id); const UUID128 &GetObjectID() const; void SetPrefabNodeID(const UUID128 &id); const UUID128 &GetPrefabNodeID() const; void SetSaveEnabled(bool enabled); bool IsSaveEnabled() const; void SetActive(bool active); bool IsActive() const; void SetEditorOnly(bool editorOnly); bool IsEditorOnly() const noexcept; bool IsEditorOnlyInHierarchy() const;

Clone() は自身の全コンポーネントを複製した新しい EmptyObject を返しますが、返り値の所有権はまだシーンに追加されていない状態です（実際にシーンへ加えるには Scene::CloneObject を使います）。SetActive(false) は自身の全コンポーネントの Finalize を、再度 true にすると Initialize を走らせます。祖先が非アクティブな場合は自身の isActive_ フラグが true でも実効的には非アクティブとして扱われ、この「実効アクティブ状態」が変化した子孫にも同様に Initialize/Finalize が波及します。

SetEditorOnly(true) を付けたオブジェクトはシーンビュー専用の補助オブジェクト（デバッグ用の目印など）として扱われ、再生開始時・エディター無しビルドでのシーン読み込み時に子孫ごと削除されます。

SetPrefabNodeID/GetPrefabNodeID はPrefab内の対応ノードを識別するための安定IDです。GetObjectID()（シーン内で一意なUUID）とは別物で、Prefabに関連しないオブジェクトでは無効なまま、Clone()でも複製されません。Prefabをシーンへ配置した際の各ノードと、元のPrefabファイル内のノードとを突き合わせるためだけに使われます。

コンポーネント管理

template<typename T> std::vector<T *> GetComponents() const; template<typename T> T *GetComponent() const; IObjectComponent *GetComponent(const IObjectComponent *component) const; template<typename T> size_t HasComponents() const; size_t HasComponent(const IObjectComponent *component) const; const std::vector<std::pair<std::unique_ptr<IObjectComponent>, size_t>> &GetAllComponents() const; IObjectComponent *AddComponent(std::unique_ptr<IObjectComponent> comp); template<typename T> T *AddComponent(std::unique_ptr<T> comp); template<typename T, typename... Args> T *AddComponent(Args&&... args); bool RemoveComponent(const IObjectComponent *component); template<typename T> bool RemoveComponent(); template<typename T> bool RemoveComponents(); void ClearComponents();

これが「コンポジションによって機能を積む」ための中心的なAPIです。AddComponent<T>(args...) は T のインスタンスを生成してオブジェクトへ追加し、追加されたコンポーネントのポインタを返します（GetMaxComponentCountPerObject() の上限に達している場合など、生成に失敗した場合は nullptr）。GetComponents<T>() は追加順にソートされた同型コンポーネントのリストを返します。

Transform は生成時に自動で1個付与される
EmptyObject は内部のコンストラクタで AddComponent<Transform>() を自動的に呼ぶため、CreateEmptyObject() で生成した時点で必ず Transform を1個持っています。Transform の最大付与数は1のため、後から AddComponent<Transform>() を呼んでも（既に1個あるため）nullptr が返るだけです。座標などを扱いたい場合は GetComponent<Transform>() で取得してください。

JSON保存/読み込み（参考情報）

JSON SaveToJson(Passkey<Scene>); bool LoadFromJson(Passkey<Scene>, const JSON &json); JSON SaveComponentToJson(const IObjectComponent *component) const; IObjectComponent *AddComponentFromJson(const JSON &json); bool LoadComponentFromJson(IObjectComponent *component, const JSON &json);

SaveToJson / LoadFromJson は Passkey<Scene> を要求するため Scene クラスの内部（シーンの保存・読み込み処理）からしか呼び出せません。ゲーム側のコードから直接呼ぶことはありませんが、「オブジェクトの状態は丸ごとJSONへシリアライズできる」という設計を理解する上での参考として掲載しています。SaveComponentToJson/AddComponentFromJson/LoadComponentFromJson はコンポーネント単体のJSONスナップショットで、シーンエディタのUndo/Redoに使われます。

Tag クラス

Utilities/Tag.h に定義される軽量なタグです。文字列から FNV-1a（64bit）ハッシュを計算して内部に保持するだけの値型で、比較（== / !=）は文字列比較ではなくハッシュ値同士の比較になるため高速です。EmptyObject だけでなく IObjectComponent / ISceneComponent にも同じ SetTag / GetTag / GetTagName のAPIがあり、オブジェクトやコンポーネントの分類・判別（例: 「Enemy」タグの付いたオブジェクトだけ処理する）に使います。

explicit Tag(const std::string &name) noexcept; constexpr std::uint64_t GetHash() const noexcept; constexpr bool IsEmpty() const noexcept; // 空文字列のタグ（未設定）かどうか constexpr bool operator==(const Tag &other) const noexcept;
if (obj->GetTag() == Tag("Enemy")) {
    // ...
}

UUID128 クラス

Utilities/UUID128.h に定義される、オブジェクトの識別子です。EmptyObject::GetObjectID() はこの型を返し、シーン内でオブジェクトを名前ではなく一意なIDで参照する際（Scene::GetSceneObject(const UUID128 &)、Transform::SetParentObject(const UUID128 &) など）に使われます。

explicit UUID128(); // 無効なUUID explicit UUID128(bool generateNew); // trueで新規UUIDを生成 explicit UUID128(const std::string &uuidStr); // 既存のUUID文字列から復元 explicit UUID128(uint64_t high, uint64_t low); void GenerateUUID(); void ResetUUID(); const std::string &ToString() const; uint64_t GetHigh() const; uint64_t GetLow() const; bool IsValid() const;

EmptyObject はデフォルトで objectID_ = UUID128(true)、つまり生成時に自動で新しいUUIDが割り当てられます。JSONへは128bit値ではなく標準的なUUID文字列表現（xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx）として保存されます。std::hash<UUID128> の特殊化も提供されているため、std::unordered_map<UUID128, ...> のキーとしてそのまま使えます。

コンポジションモデル: 「積んでいく」考え方

EmptyObject はそれ自体では何もしません。名前・タグ・アクティブ状態・コンポーネントのリストを持つだけの入れ物です。「座標を持つ」「メッシュを描画する」「当たり判定を持つ」「スクリプトで動く」といった具体的な振る舞いは、すべて AddComponent<T>() で追加する IObjectComponent 派生クラスが担います。 

// 例: シーンコンポーネントの Initialize 内などで SceneContext 経由で組み立てる場合
EmptyObject *player = sceneContext->CreateEmptyObject("Player");

// Transform は生成時に自動で付与されているので GetComponent で取得する（座標・回転・スケールを持たせる）
Transform *transform = player->GetComponent<Transform>();
transform->SetTranslate({ 0.0f, 0.0f, 0.0f });

// MeshFilter を積む（描画するメッシュを持たせる）
player->AddComponent<MeshFilter>(playerMeshHandle);

// Velocity を積む（速度・加速度でTransformを毎フレーム動かす）
Velocity *velocity = player->AddComponent<Velocity>();
velocity->SetVelocity({ 1.0f, 0.0f, 0.0f });

同じ型のコンポーネントを何個まで付けられるかはコンポーネント側が GetMaxComponentCountPerObject() として宣言しています（例えば Transform は1個まで、Comment のようなデバッグ用途のものは複数可、というように種類ごとに異なります。詳細は 04_ObjectComponents.html を参照）。

実際の使い方は主にシーンエディタ／AngelScript
上記のようなC++コードは、エンジン内部のシステムコンポーネント（SceneRenderer や SceneScriptEngine 等）を実装する際には登場しますが、一般的なゲームコンテンツ制作では基本的にオブジェクトの生成とコンポーネントの付与はシーンエディタ上で行い、動的な生成（弾を撃つ、敵をスポーンさせる等）はAngelScriptスクリプトから行います。01_Overview.html で触れた通り、ゲーム側のC++コードは実質 AppInitialize.h 1ファイルのみに留めるのがこのエンジンの想定する使い方です。詳しくは Script/00_Index.html を参照してください。
