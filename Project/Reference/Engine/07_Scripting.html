AngelScriptでのゲームロジック

KashipanEngineでは、プレイヤー移動・当たり判定への応答・演出・UI操作といった実際のゲームロジックのほとんどを、C++ではなく AngelScript（.asファイル）で書き、ScriptComponent としてオブジェクトへアタッチします。エンジン本体の再ビルドなしに挙動を調整・追加できることが最大の利点です。このページではその書き方とスクリプトから利用できるAPIをまとめます。

なぜAngelScriptを使うのか

01_Overview.html で触れたとおり、EmptyObject や各種コンポーネントはほとんどが final 指定されており、C++側で継承して独自のオブジェクト型・コンポーネント型を作るという設計にはなっていません。振る舞いを追加したい場合の選択肢は次の2つです。

方法向いている用途
C++の IObjectComponent 派生クラスを増やすエンジン全体で汎用的に使う基盤機能（描画・物理・入力など）。ビルドが必要
AngelScriptで ScriptComponentBehavior を実装する個々のゲーム・ステージ・キャラクター固有のロジック。ビルド不要でリロードして即確認できる
ポイント
プレイヤーの移動・ジャンプ・被ダメージ、敵のAI、ギミック（動く床・チェックポイント・回転オブジェクト等）、演出制御など、「このゲーム固有の振る舞い」はほぼ例外なくスクリプトで書きます。C++側のコンポーネント（Transform, Velocity, MeshRenderer, 各種コライダー等）は、スクリプトから読み書きする「データの入れ物」「土台となる機能」として使われます。

ScriptComponentの付け方

スクリプトを実行するには、対象オブジェクトへ ScriptComponent をアタッチし、実行する .as ファイルのパスを指定します。実運用では大半のオブジェクトがシーンエディタ上でEmptyObjectを作り、インスペクターからScriptComponentを追加してスクリプトファイルを選択する形で設定されます（詳細は Editor/Architecture/01_Overview.html（シーンエディタ） 参照）。コードから明示的に追加する場合は次のようになります。 

EmptyObject *obj = scene->CreateEmptyObject("Player");
ScriptComponent *script = obj->AddComponent<ScriptComponent>();
script->SetScriptPath("Assets/Application/Scripts/Player.as");

ScriptComponent final

void SetScriptPath(const std::string &scriptPath); const std::string &GetScriptPath() const noexcept; bool Reload(); const std::string &GetLastError() const noexcept; bool GetVariable(const std::string &name, void *ref, int typeId) const; bool SetVariable(const std::string &name, void *ref, int typeId); std::vector<std::string> GetFloatVariableNames() const; bool SetFloatVariable(const std::string &name, float value);

SetScriptPath() でファイルを指定した後、実際にコンパイル・インスタンス化を行うのは Reload() です（Initialize() 内から自動で1回呼ばれるため、通常は意識する必要はありません）。GetVariable/SetVariable は他オブジェクトの ScriptComponent を GetComponent で取得した上で、その [SerializeField] 変数を名前指定で直接読み書きするためのものです（スクリプト間のデータ受け渡し手段の1つ。詳しくは後述の「シーン変数」とあわせて参照してください）。

実行に必要な共有スクリプトエンジンはシーンコンポーネント SceneScriptEngine（Scene/Components/Script/SceneScriptEngine.h）が保持しており、ScriptComponent::Initialize() 時にシーンへ未追加ならば自動で追加されます。ゲーム側で意識する必要は基本的にありません。

スクリプトの基本形

1つの .as ファイルの中に、インターフェース ScriptComponentBehavior を実装したクラスを1つ定義します。ScriptComponent はビルド後にモジュール内からこのインターフェースを実装したクラスを探してインスタンス化し、以降のライフサイクル関数を呼び出します。 

// AlwaysRotate.as
// 毎フレーム一定の角速度でオブジェクトを回転させ続けるだけのスクリプト
class AlwaysRotate : ScriptComponentBehavior {
    // 各軸の角速度（ラジアン/秒）
    [SerializeField]
    Vector3 angularVelocity = Vector3(0.0f, 0.0f, 1.0f);

    void Update() {
        Transform@ tf = GetTransform();
        if (tf is null) return;

        float dt = GetDeltaTime() * GetGameSpeed();
        if (dt < 0.0f) dt = 0.0f;

        tf.SetRotate(tf.GetRotate() + angularVelocity * dt);
    }
}

クラス名はファイル名と一致させる必要はありませんが、慣習として一致させます。GetTransform() や GetDeltaTime() のようにオブジェクトを介さず直接呼べているグローバル関数は、後述の「スクリプトAPIリファレンス」で一覧にしている、エンジンが登録したグローバル関数です。

ライフサイクル関数

ScriptComponentBehavior を実装したクラスの中に以下のメソッドを定義すると、ScriptComponent が該当するタイミングで自動的に呼び出します（全て省略可能。実装したものだけが呼ばれます）。

関数呼ばれるタイミング
void Awake()インスタンス生成時（コンポーネントとしてアタッチされた時。Reload() 成功時も含む）に一度だけ
void Start()ゲームループ中、そのインスタンスに対して最初に Update() が呼ばれる直前に一度だけ
void Update()毎フレーム
void End()終了時（コンポーネント削除・非アクティブ化・リロード時）
void OnCollisionEnter(const HitInfo &in hit)同オブジェクトのコライダーが他コライダーと接触し始めた時
void OnCollisionStay(const HitInfo &in hit)同オブジェクトのコライダーが他コライダーと接触し続けている間、毎フレーム
void OnCollisionExit(const HitInfo &in hit)同オブジェクトのコライダーが他コライダーとの接触を終えた時
void OnWindowMessage(const WindowMessageInfo &in info)同オブジェクトの NormalWindowObject/OverlayWindowObject 等のウィンドウがメッセージを受信した時（通知元コンポーネント情報付き）
衝突コールバックの実例
Player.as は OnCollisionEnter/OnCollisionStay/OnCollisionExit の3つ全てを使い、地面判定・敵接触判定・押し戻しを行っています。詳しくは後述の実例セクションを参照してください。コライダー・当たり判定応答の仕組み自体は 06_Collision.html にまとまっています。
OnCollisionEnter/Stay/Exit と OnWindowMessage はコストがある
これらのコールバックは、内部で同オブジェクトの全コライダー（または全WindowObject系コンポーネント）へフックを張ることで実現されています。実装したメソッドを持つスクリプトだけがこのフック対象になるため、使わないなら定義しないほうが軽量です。

SerializeField属性

クラスのメンバ変数（またはグローバル変数）に [SerializeField] メタデータを付けると、シーンエディタのインスペクター上で編集でき、シーンへの保存・読込の対象になります。Reload() でスクリプトを再コンパイルしても、[SerializeField] 付き変数の現在値は維持されます。

属性効果
[SerializeField]インスペクター表示・シーン保存の対象にする（これが無いと単なる実行時の一時変数として扱われる）
[Range(min, max)]数値をスライダーで編集できるようにする
[Header("見出し")]インスペクター上に見出しを挿入する
[Tooltip("説明")]インスペクター上でホバー時に説明を表示する
[ColorPicker]Vector4 をRGBA色として編集するUIにする
[Multiline] / [TextArea(minLines, maxLines)]文字列を複数行のテキストエリアで編集する
[Space(高さpx)]インスペクター上に余白を挿入する

1つの属性ブロックへカンマ区切りでまとめて記述できます（Player.as より）。 

[Header("プレイヤーの基本設定")]

[SerializeField, Tooltip("移動速度")]
float moveSpeed = 0.1f;

[SerializeField, Tooltip("最大速度")]
Vector3 maxVelocity = Vector3(8.0f, 16.0f, 8.0f);

WaypointCurve.as では [Range] を uint 変数へ付与しています。

[SerializeField, Range(2, 64), Tooltip("区間ごとの分割数。大きいほど曲線の精度・滑らかさが上がる")]
uint samplesPerSegment = 16;

対応する型

[SerializeField] が対応する型は次のとおりです。

  • プリミティブ型: bool / int / uint / float / double / string
  • 数学型: Vector2 / Vector3 / Vector4 / Quaternion
  • Object@（シーン内オブジェクトへの参照。インスペクターでコンボからの選択、およびヒエラルキーからのドラッグ&ドロップで指定できる）
  • [System.Serializable] を付けたスクリプトクラス（public変数は自動的にシリアライズ対象、private/protected変数は個別に [SerializeField] が必要）
  • 上記対応型の array<T>（ネストした配列、Serializableクラスの配列も可）
array<T> は必ずハンドル構文＋null初期値で宣言する
array<T>@ 変数名 = null; のように、必ず明示的なハンドル構文（@）と null 初期値で宣言してください。array<T> 変数名; のような値的構文はAngelScript側のGC追跡が壊れ、インスペクター表示時やエンジン終了時にクラッシュします（壊れたハンドルは検出時に自動で新しい空配列へ差し替えられますが、根本原因はスクリプト側の宣言にあるため必ず正しい書き方をしてください）。

Tag 型は [SerializeField] の対応型に含まれません。タグ名をインスペクターから編集したい場合は CenterRiderOnFloor.as のように文字列（または array<string>）として保持し、比較時に Tag(name) へ変換します。 

// TagはSerializeFieldの対応型に含まれないため、文字列配列として保持し比較時にTag化する
[SerializeField, Tooltip("この処理を行わない相手オブジェクトのタグ名（複数指定可）")]
array<string>@ excludedTagNames = null;

配列を実行時に初期化する場合は、WaypointCurve.as の Start() のように null チェックしてから生成します。 

array<Vector3>@ controlPoints = null;

void RebuildCurve() {
    if (controlPoints is null) @controlPoints = array<Vector3>();
    controlPoints.resize(0);
    // ...
}

スクリプトAPIリファレンス

スクリプトからは KashipanEngine/Scene/Components/Script/ScriptBindings.cpp の RegisterEngineScriptBindings() で登録された型・関数を利用できます。以下は実際に登録されているものの抜粋です（エンジンの全機能を網羅しているわけではありませんが、代表的なものはほぼ含まれています）。

補完ファイル as.predefined
エンジンは起動時に、登録済みの型・関数一式からVSCodeのAngelScript Language Server用の型定義ファイル as.predefined を自動生成します（GenerateScriptPredefinedFile()）。エディタ補完に迷ったら、このファイルを見れば現在ビルドに登録されている全シグネチャを確認できます。

実行コンテキストの取得（オブジェクト自身に関する関数）

これらはスクリプトの実行中、そのスクリプトをアタッチしているオブジェクトを暗黙の対象として動作するグローバル関数です。

関数説明
Object@ GetOwnerObject()このスクリプトがアタッチされているオブジェクトを取得する
Transform@ GetTransform()オーナーオブジェクトの Transform コンポーネントを取得する（GetOwnerObject().GetTransform() の省略形）
Scene@ GetScene()現在のシーンを取得する
Object@ FindObject(const string &in name)シーン内から名前でオブジェクトを検索する
bool IsValidObject(Object@ obj)渡されたオブジェクトが現在も生存しているかを、シーンが保持する生存集合との照合で安全に判定する（[SerializeField]等で保持したハンドルが指す先が削除済みでも安全に呼べる）
bool GetComponent(?&out)オーナーオブジェクトから指定型のコンポーネントを1つ取得する
bool GetComponents(?&out)オーナーオブジェクトから指定型のコンポーネントを全て取得する（array<T@>@ で受ける）
bool AddComponent(?&out)オーナーオブジェクトへ指定型のコンポーネントを追加する

Object 型自身にも同名の GetComponent/GetComponents/AddComponent/RemoveComponent メソッドがあるため、他オブジェクトに対しては someObject.GetComponent(@velocity) のように呼び出します。 

// 自分自身
MeshRenderer@ meshRenderer;
if (GetComponent(@meshRenderer)) {
    meshRenderer.SetInstanceColor(Vector4(1.0f, 0.2f, 0.2f, 1.0f));
}

// 他オブジェクト（衝突相手など）
Transform@ groundTransform;
if (hit.otherObject.GetComponent(@groundTransform)) {
    // ...
}

実例: Player.as を読み解く

Assets/Application/Scripts/Player.as は、移動・坂道判定・ジャンプ・被ダメージ・チェックポイント復帰までを1つのスクリプトで実装した、このエンジンにおけるスクリプティングの実践例です。全体は300行超あるため、ここでは要点を抜粋しながら解説します。

SerializeFieldでパラメータを外出しする

[Header("プレイヤーの基本設定")]

[SerializeField, Tooltip("移動速度")]
float moveSpeed = 0.1f;
[SerializeField, Tooltip("ジャンプ力")]
float jumpPower = 16.0f;
[SerializeField, Tooltip("重力")]
float gravity = 0.2f;
...
[Header("移動方向追従オブジェクト")]

[SerializeField, Tooltip("プレイヤーの移動方向の先へ配置するオブジェクト")]
Object@ movementTargetObject;

移動速度・ジャンプ力・重力・HP・ノックバック量など、調整が必要な値を全て [SerializeField] にすることで、C++の再ビルドはおろかスクリプトの再コンパイルすら不要に、インスペクター上の数値変更だけでゲームバランスを調整できます。Tooltip を添えておくと、他の開発者（あるいは未来の自分）がインスペクター上でパラメータの意味をすぐ把握できます。

Update()で毎フレームの処理を段階分けする

void Update() {
    const float dt = GetDeltaTime() * GetGameSpeed();
    const bool wasGroundedAtFrameStart = isGrounded;

    InputEvent();
    UpdateGroundedState(dt);
    Landing();
    LateralMovement();
    Sliding(dt);
    Jumping(dt);
    UpdatePlatformInertia(dt, wasGroundedAtFrameStart);
    UpdateDamageCooldown(dt);
    CheckEnemyDamage();
    ApplyVelocity(dt);
    UpdateDamageFlash(dt);
    CheckDeath();
    UpdateMovementTarget();

    hasGroundContact = false;
    isCollidingWithEnemy = false;
}

dt は GetDeltaTime() * GetGameSpeed() で求めます。GetGameSpeed() を掛けておくことで、スロー演出やポーズ相当の速度変更に自動で追従します。Update() 本体はこの1フレーム分の処理を意味のある単位（入力・接地判定・移動・重力・被ダメージ…）の private メソッドへ分割して呼び出しているだけで、それぞれのメソッド自体はさほど複雑ではありません。大きなロジックは1つの関数に詰め込まず、こうして分割していくと見通しがよくなります。

OnCollisionStay()で地面判定・押し戻し・動く床への追従を行う

void OnCollisionStay(const HitInfo &in hit) {
    if (hit.otherObject is null) return;
    if (hit.otherCollider !is null && hit.otherCollider.IsTrigger()) return;
    if (hit.otherCollider.GetTag() == groundColliderTag) {
        bool grounded = hit.normal.y > groundedThreshold;
        if (!hasGroundContact && grounded) {
            hasGroundContact = true;
            groundHitNormal = hit.normal;
            isOnSteepSlope = hit.normal.y < slideThreshold;
        } else if (!grounded) {
            // 壁・天井：法線方向の速度成分だけを打ち消す
            Vector3 wallNormal = hit.normal;
            wallNormal.z = 0.0f;
            float intoSurface = velocity.Dot(wallNormal);
            if (intoSurface < 0.0f) {
                velocity = velocity - wallNormal * intoSurface;
            }
        }

        // 動く床への追従：地面のTransformとPreTransform（前フレーム値）の差分を使う
        if (grounded) {
            Transform@ groundTransform;
            PreTransform@ groundPreTransform;
            if (hit.otherObject.GetComponent(@groundTransform) && hit.otherObject.GetComponent(@groundPreTransform)) {
                groundDelta = groundTransform.GetTranslate() - groundPreTransform.GetPreviousTranslate();
            }
        }

        // 押し戻し
        Transform@ tf = GetTransform();
        if (tf !is null) {
            Vector3 pushBack = hit.normal * hit.penetration;
            pushBack.z = 0.0f;
            if (grounded) pushBack.x = 0.0f;
            tf.SetTranslate(tf.GetTranslate() + pushBack);
        }
    }
}

このメソッドから読み取れる実践的なパターンをいくつか挙げます。

  • hit.otherCollider.GetTag() によるタグ比較でコライダーの種別を判定する（Tag groundColliderTag = Tag("GroundBox"); のようにあらかじめ構築しておいたタグと比較する）
  • hit.otherCollider.IsTrigger() でトリガー判定のコライダーは押し戻し処理から除外する
  • hit.normal * hit.penetration で押し戻しベクトルを作り、Transform へ直接加算して位置補正する
  • 地面側の Transform と PreTransform（前フレームの値）の差分から動く床への追従量を求める（Velocity コンポーネントを直接見るのではなく差分ベースにすることで、地面がスクリプトから直接 Transform を書き換えるような動かし方をしていても正しく追従できる）

シーン変数によるチェックポイント連携

Checkpoint.as は接触時に自身の位置をシーン変数へ保存します。 

// Checkpoint.as
void TrySave(const HitInfo &in hit) {
    if (hit.otherObject is null) return;
    if (hit.otherCollider is null || hit.otherCollider.GetTag() != playerColliderTag) return;

    Transform@ tf = GetTransform();
    Scene@ scene = GetScene();
    if (tf is null || scene is null) return;

    int savedPriority;
    bool hasSaved = scene.GetVariable("CheckpointPriority", savedPriority);
    if (hasSaved && savedPriority > priority) return; // より優先度の高いチェックポイントは上書きしない

    scene.SetVariable("CheckpointPosition", tf.GetTranslate());
    scene.SetVariable("CheckpointPriority", priority);
}

Player.as 側は、HPが尽きたときにこの値を読み出してリスポーンします。 

// Player.as
void CheckDeath() {
    if (currentHp > 0) return;

    Transform@ tf = GetTransform();
    Scene@ scene = GetScene();
    Vector3 respawnPosition;
    bool hasCheckpoint = (scene !is null) && scene.GetVariable("CheckpointPosition", respawnPosition);
    if (tf !is null && hasCheckpoint) {
        tf.SetTranslate(respawnPosition);
    }

    velocity = Vector3(0.0f, 0.0f, 0.0f);
    currentHp = maxHp;
    damageCooldownTimer = damageCooldown; // リスポーン直後の無敵猶予として流用
}

このように、直接の参照関係を持たない2つのオブジェクト（チェックポイントとプレイヤー）が、文字列キーのシーン変数だけを介して疎結合に連携できる点がシーン変数の利点です。GetVariable は値が存在しない・型が一致しない場合に false を返すため、bool hasCheckpoint = ... のように戻り値を必ずチェックしてから使います。

被ダメージ演出とMeshRendererの色操作

void UpdateDamageFlash(const float dt) {
    if (damageFlashTimer <= 0.0f) return;
    damageFlashTimer -= dt;

    MeshRenderer@ meshRenderer;
    if (!GetComponent(@meshRenderer)) return;
    bool blinkOn = (int(damageFlashTimer / damageFlashInterval) % 2) == 0;
    if (blinkOn) {
        meshRenderer.SetInstanceColor(damageFlashColor);
        meshRenderer.SetInstanceColorBlendMode(0); // Override
    } else {
        meshRenderer.SetInstanceColor(Vector4(1.0f, 1.0f, 1.0f, 1.0f));
        meshRenderer.SetInstanceColorBlendMode(1); // Multiply（見た目に影響しない）
    }
}

無敵時間中、経過時間をダメージ点滅間隔で割った商の偶奇で点滅させています。MeshRenderer::SetInstanceColorBlendMode は整数でブレンドモード（0=Override, 1=Multiply, 2=Add, 3=Subtract）を指定するため、コメントで意味を残しておくと読みやすくなります。

リロードとエラー確認

ScriptComponent::Reload() はスクリプトファイルを再コンパイルします。既にビルド済みの場合は内部で End() を呼んでから再構築するため、状態のクリーンアップは自動で行われます。[SerializeField] 付き変数の現在値はリロード後も維持されます。

シーンエディタでの実行時リロード
シーンエディタ（Editor/Architecture/01_Overview.html（シーンエディタ））上でスクリプトを編集して保存すると、多くの場合インスペクターから Reload() を呼ぶ導線が用意されています。コンパイルエラーがあった場合は再構築が失敗し、直前の状態（あるいは未ビルド状態）のまま残ります。 
ScriptComponent *script = obj->GetComponent<ScriptComponent>();
if (!script->Reload()) {
    // コンパイル/実行時エラーの内容を取得できる
    Log::Error(script->GetLastError());
}
エラーは静かに失敗する
Reload() が false を返しても例外は投げられません。スクリプトが動いていないように見える場合は、まず GetLastError()（内部的には直近のビルド失敗時のコンパイルメッセージ）を確認してください。よくある原因は、クラス名の変更後に ScriptComponentBehavior を実装したクラスが見つからない、[SerializeField] の型が非対応、array<T> をハンドル構文で宣言していない、といったものです。
