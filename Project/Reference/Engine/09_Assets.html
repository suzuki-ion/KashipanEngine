アセット管理

テクスチャ・モデル・マテリアル・サンプラー・スケルトン/アニメーション・フォント・音声を扱う各種 *Manager クラスをまとめます。すべて共通の設計パターンを踏襲しているため、まず共通パターンを押さえると各マネージャの理解が早くなります。

共通パターン: パス → ハンドル → コンポーネントへ設定

KashipanEngine/Assets/ 配下の各マネージャ（TextureManager / ModelManager / MaterialManager / SkeletonManager / AnimationManager / FontManager / AudioManager）は、いずれも次の設計に従います。

  • コンストラクタは Passkey<GameEngine> 限定 … ゲーム側からインスタンスを直接生成することはできません。GameEngine が起動時に1つずつ生成し、Assets/ フォルダ以下を走査して自動的に全アセットを読み込みます（LoadAllFromAssetsFolder()）。
  • 読み込みは軽量な整数ハンドルを返す … TextureManager::TextureHandle のような uint32_t のエイリアス型で、無効値は kInvalidHandle（0）系の定数です。
  • 取得は基本的に static メソッド … 実行中は各マネージャのインスタンスが常に1つだけ存在する前提で、ハンドル・ファイル名・Assetsルートからの相対パスのいずれからでもデータ/ハンドルを引けます（GetXxxFromFileName / GetXxxFromAssetPath)。
  • コンポーネントは「名前」を保存し、ハンドルは遅延解決する … MeshFilter や MeshRenderer、AudioSource のようなコンポーネントは、シリアライズ時にはハンドル値ではなくアセットパス（文字列）を保存し、実行時に初めて使われたタイミングで GetXxxHandleFromAssetPath() 等を呼んでハンドルへ解決します。ハンドル値は読み込み順やアセット数で変わり得るため、保存には向きません。
  • リネーム/移動は RenameXxx() で登録側へ反映する … TextureManager::RenameTexture / ModelManager::RenameModel / MaterialManager::RenameMaterialFile / AudioManager::RenameSound はいずれも「Assetsウィンドウ等で実ファイルをリネーム/移動した後に呼ぶと、登録済みのファイル名/パスを新しい値へ更新する」静的メソッドです（実ファイル自体は操作しません）。
// MeshFilter::LoadFromJson の例（アセットパスの文字列からハンドルへ遅延解決する典型パターン）
bool LoadFromJson(const JSON &json) override {
    const std::string assetPath = json.value("meshAssetPath", std::string());
    meshHandle_ = assetPath.empty()
        ? ModelManager::kInvalidHandle
        : ModelManager::GetModelHandleFromAssetPath(assetPath);
    return true;
}
ポイント
自前でアセットを読み込みたい場合は、各マネージャの LoadXxx(filePath)（TextureManager::LoadTexture 等）を呼べば、Assetsフォルダ自動走査の対象外のファイルでも個別に読み込めます。ただし通常は Assets/ 以下に置くだけでエンジン起動時に自動登録されるため、明示的な読み込み呼び出しは必須ではありません。

ModelManager

読み込みとハンドル取得

using ModelHandle = uint32_t; ModelHandle LoadModel(const std::string &filePath); static ModelHandle GetModelHandleFromFileName(const std::string &fileName); static ModelHandle GetModelHandleFromAssetPath(const std::string &assetPath); static ModelHandle RegisterProceduralMesh(const std::string &name, std::vector<ModelData::Vertex> vertices, std::vector<std::uint32_t> indices); static std::string GetBaseAssetPath(const std::string &assetPath);

複数メッシュノードを持つモデルは、ノードごとに "モデルパス:ノード名" という形式のアセットパスでサブメッシュとして個別登録されます。GetBaseAssetPath はそこから元のモデルファイルパスへ戻すためのヘルパーです（スケルトン/アニメーションはモデルファイル単位で管理されるため）。

環境マップ・法線マップはモジュール化されている
以前は Material が environmentHandle（環境マップ）・normalMapHandle（法線マップ）・environmentCoefficient を直接持っていましたが、現在はシェーダーモジュール機構（AO・スペキュラー・オパシティ・ディテールマップなども含む）へ再構成されており、これらのフィールドは Material 構造体には存在しません。モジュール単位のパラメータは extraParameters 経由でシェーダーとやり取りされます。詳細は 05_Rendering.html を参照してください。

SamplerManager

サンプラー管理

using SamplerHandle = uint32_t; static SamplerHandle CreateSampler(const D3D12_SAMPLER_DESC &desc); static SamplerHandle GetSampler(DefaultSampler state); static bool BindSampler(ShaderVariableBinder *shaderBinder, const std::string &nameKey, SamplerHandle handle); static bool BindSampler(ShaderVariableBinder *shaderBinder, const std::string &nameKey, DefaultSampler defaultSampler);

DefaultSampler 列挙型はエンジンが起動時に用意する既定サンプラー（PointClamp / PointWrap / LinearClamp / LinearWrap / AnisotropicClamp / AnisotropicWrap）です。多くの場合、独自サンプラーを作らずこれらを GetSampler() で取得して使えば十分です。

SkeletonManager / AnimationManager

スケルタルアニメーションは、モデル本体（ModelManager）・骨格構造（SkeletonManager）・アニメーションクリップ（AnimationManager）の3つのマネージャに分かれて管理されます。実際の再生・描画は 05_Rendering.html の SkinnedMeshRenderer を参照してください。

SkeletonManager

using SkeletonHandle = uint32_t; SkeletonHandle LoadSkeleton(const std::string &filePath); static SkeletonHandle GetSkeletonHandleFromFileName(const std::string &fileName); static SkeletonHandle GetSkeletonHandleFromAssetPath(const std::string &assetPath); static const SkeletonData &GetSkeletonData(SkeletonHandle handle); static const bool UpdateSkeletonJointTransforms(SkeletonHandle handle); static void ResetAllSkeletonsToBindPose(); static Skeleton CloneSkeleton(SkeletonHandle handle);

SkeletonData はノード階層（GetRootNode()）とジョイント一覧（GetSkeleton()）を持ちます。複数の SkinnedMeshRenderer が同じスケルトンアセットを共有していても再生状態が干渉しないよう、各インスタンスは CloneSkeleton() で複製した自分専用のジョイント階層を使います。

AnimationManager

using AnimationHandle = uint32_t; AnimationHandle LoadAnimation(const std::string &filePath); static AnimationHandle GetAnimationHandleFromFileName(const std::string &fileName); static const std::vector<AnimationHandle> &GetAnimationHandlesFromFileName(const std::string &fileName); static AnimationHandle GetAnimationHandleFromAssetPath(const std::string &assetPath); static const AnimationData &GetAnimationData(AnimationHandle handle);

AnimationData は複数の AnimationClip（名前・長さ・タイムライン）を保持します。AnimationClip::timelines は KeyframeAnimator と共通の KeyframeTimeline 型です。

FontManager

読み込みとグリフ取得

using FontHandle = std::uint32_t; static FontHandle LoadFont(const std::string &filePath); static FontHandle GetFontHandleFromFileName(const std::string &fileName); static FontHandle GetFontHandleFromAssetPath(const std::string &assetPath); static FontHandle GetFontHandleFromName(const std::string &name); static const GlyphInfo *GetOrBakeGlyph(FontHandle handle, char32_t codepoint); static const GlyphInfo *GetSolidGlyph(FontHandle handle); static TextureManager::TextureHandle GetAtlasTextureHandle(FontHandle handle); static float GetScaleForPixelHeight(FontHandle handle, float pixelHeight); static float GetLineHeight(FontHandle handle, float pixelHeight); static float GetAscent(FontHandle handle, float pixelHeight); static float GetDescent(FontHandle handle, float pixelHeight);

TTF/OTFフォントを読み込み、グリフをSDF（Signed Distance Field）としてフォントごとに1枚のアトラステクスチャへ遅延ベイクします（初めて要求されたコードポイントのみビットマップ化）。SDFは解像度非依存で拡大縮小できるため、表示サイズごとにアトラスを作り直す必要はありません。アトラスは GetAtlasTextureHandle() で通常のテクスチャとして取得できるため、TextureManager の仕組みにそのまま乗せてバインドできます。テキスト描画コンポーネントの詳細な使い方は各描画系ページに譲ります。

AudioManager

音声の読み込みと再生を管理するクラスです。ハンドルは「読み込んだ音声を指す SoundHandle」と「実際に再生中のインスタンスを指す PlayHandle」の2種類に分かれます。同じ SoundHandle から複数の PlayHandle（多重再生）を作ることができます。

読み込み

再生・停止・一時停止

再生パラメータの変更

static bool SetVolume(PlayHandle play, float volume); // 0.0f～1.0f static bool SetPitch(PlayHandle play, float pitch); // 半音単位 static bool SetPan(PlayHandle play, float pan); // -1.0f(左)～1.0f(右)

エフェクト

enum class FilterType { LowPass, HighPass, BandPass, Notch }; static bool SetFilter(PlayHandle play, FilterType type, float frequency, float oneOverQ = 1.0f); static bool SetReverbSend(PlayHandle play, float wetLevel); static bool SetEqEffect(PlayHandle play, bool enabled, const EqParams &params); // 4バンドイコライザー static bool SetEchoEffect(PlayHandle play, bool enabled, const EchoParams &params); // やまびこ static bool SetLimiterEffect(PlayHandle play, bool enabled, const LimiterParams &params); // マスタリングリミッター

フィルター（SetFilter）とリバーブ送り（SetReverbSend）は毎フレームでも呼びやすい軽量な設定変更用、イコライザー/エコー/リミッターはエフェクトチェーンの有効・無効を切り替える系のAPIです。frequency は正規化カットオフ周波数（0に近いほど強くかかり、1.0でフィルター無しと同等）、oneOverQ は共鳴の鋭さです。

注意
AudioManager の再生系メソッドはすべて static です。しかし内部的には現在アクティブな唯一のインスタンス（GameEngineが生成したもの）を経由するため、ゲームループ実行中であればどこからでも安全に呼び出せます。

オブジェクトへの音声コンポーネント: AudioSource / AudioListener

シーン上のオブジェクトから音声を再生・受聴するには、AudioManager を直接呼ぶのではなく Objects/Components/AudioSource.h / AudioListener.h の2つのコンポーネントを使うのが基本です（04_ObjectComponents.html 参照）。

AudioSource final

void SetSoundName(const std::string &soundName); // アセットパス or ファイル名 void SetVolume(float volume); // 0.0f～1.0f void SetPitch(float pitch); // 半音単位 void SetLoop(bool loop); void SetMinDistance(float minDistance); void SetMaxDistance(float maxDistance); void SetEnableSpatialAudio(bool enable); // AudioListenerとの位置関係で自動パン/籠り AudioManager::PlayHandle Play(); void Stop(); bool Pause(); bool Resume(); bool IsPlaying() const; bool IsPaused() const; void SetFilterEffect(const FilterEffect &effect); void SetReverbEffect(const ReverbEffect &effect); void SetEchoEffect(const EchoEffect &effect); void SetEqEffect(const EqEffect &effect); void SetLimiterEffect(const LimiterEffect &effect);

AudioManager の低レベルAPIをラップし、Min/Max Distanceに基づく減衰や、enableSpatialAudio_ が有効な場合は使用中の AudioListener との位置関係から左右パンとローパスの籠り具合を毎フレーム自動更新します（同一シーンの SceneAudioPlayer が仲介します）。フィルター/リバーブ/エコー/イコライザー/リミッターの各エフェクトは個別に enabled を切り替えられ、複数同時に適用できます。

AudioListener final

void SetUsed(bool used); // trueにすると同一シーン内の他のAudioListenerは自動でオフになる bool GetUsed() const noexcept;

音声の受聴位置となるコンポーネントです。シーン内で同時に「使用中」になれる AudioListener は常に高々1つで、SetUsed(true) を呼ぶと他のリスナーは自動的にオフになります。シーンに1つも使用中のリスナーが無い状態で AudioListener が追加されると、自動的にそのリスナーが使用中になります。
