AngelScriptでのゲームロジック

KashipanEngineでは、プレイヤー移動・当たり判定への応答・演出・UI操作といった実際のゲームロジックのほとんどを、C++ではなく AngelScript（.asファイル）で書き、ScriptComponent としてオブジェクトへアタッチします。エンジン本体の再ビルドなしに挙動を調整・追加できることが最大の利点です。このセクションでは、ゲームプレイ用スクリプト（ScriptComponent）とエディタ拡張用スクリプト（EditorTool）の両方について、書き方とスクリプトから利用できるAPIをまとめます。

なぜAngelScriptを使うのか

01_Overview.html で触れたとおり、EmptyObject や各種コンポーネントはほとんどが final 指定されており、C++側で継承して独自のオブジェクト型・コンポーネント型を作るという設計にはなっていません。振る舞いを追加したい場合の選択肢は次の2つです。

方法向いている用途
C++の IObjectComponent 派生クラスを増やすエンジン全体で汎用的に使う基盤機能（描画・物理・入力など）。ビルドが必要
AngelScriptで ScriptComponentBehavior を実装する個々のゲーム・ステージ・キャラクター固有のロジック。ビルド不要でリロードして即確認できる
ポイント
プレイヤーの移動・ジャンプ・被ダメージ、敵のAI、ギミック（動く床・チェックポイント・回転オブジェクト等）、演出制御など、「このゲーム固有の振る舞い」はほぼ例外なくスクリプトで書きます。C++側のコンポーネント（Transform, Velocity, MeshRenderer, 各種コライダー等）は、スクリプトから読み書きする「データの入れ物」「土台となる機能」として使われます。

基本的な使い方

  1. .as 拡張子のスクリプトファイルを作成する
  2. 対象オブジェクトへ ScriptComponent をアタッチする（エディター上ではインスペクターの Add Component → Script → ScriptComponent）
  3. インスペクターの Script Path にスクリプトファイルのパスを設定する
  4. スクリプト内で ScriptComponentBehavior を実装したクラスを定義する

実運用では大半のオブジェクトがシーンエディタ上でEmptyObjectを作り、インスペクターからScriptComponentを追加してスクリプトファイルを選択する形で設定されます（詳細は Editor/Architecture/01_Overview.html（シーンエディタ） 参照）。コードから明示的に追加する場合は次のようになります。 

EmptyObject *obj = scene->CreateEmptyObject("Player");
ScriptComponent *script = obj->AddComponent<ScriptComponent>();
script->SetScriptPath("Assets/Application/Scripts/Player.as");

ScriptComponent final

void SetScriptPath(const std::string &scriptPath); const std::string &GetScriptPath() const noexcept; bool Reload(); const std::string &GetLastError() const noexcept; bool GetVariable(const std::string &name, void *ref, int typeId) const; bool SetVariable(const std::string &name, void *ref, int typeId); std::vector<std::string> GetFloatVariableNames() const; bool SetFloatVariable(const std::string &name, float value); bool InvokeMethod(const std::string &name); bool InvokeMethod(const std::string &name, void *argRef, int argTypeId);

SetScriptPath() でファイルを指定した後、実際にコンパイル・インスタンス化を行うのは Reload() です（Initialize() 内から自動で1回呼ばれるため、通常は意識する必要はありません）。GetVariable/SetVariable は他オブジェクトの ScriptComponent を GetComponent で取得した上で、その [SerializeField] 変数を名前指定で直接読み書きするためのものです。InvokeMethod（スクリプト側では CallMethod）は同様に他オブジェクトの ScriptComponent 経由で、相手のBehaviorインスタンスが持つ引数0〜1個・戻り値無しの関数を名前指定で呼び出すためのものです（詳しくは 04_ObjectSceneVariables.html の「ScriptComponent経由のスクリプト間データ受け渡し」参照）。

実行に必要な共有スクリプトエンジンはシーンコンポーネント SceneScriptEngine（Scene/Components/Script/SceneScriptEngine.h）が保持しており、ScriptComponent::Initialize() 時にシーンへ未追加ならば自動で追加されます。ゲーム側で意識する必要は基本的にありません。

  • スクリプトは ScriptComponent ごとに独立したモジュールとしてコンパイルされます。
  • インスペクターの Reload ボタンでスクリプトを再コンパイルできます（[SerializeField] 付き変数の値は維持されます。詳細は 14_Notes.html）。
  • コンパイルエラー・実行時例外はエンジンのログとインスペクターに出力されます。
  • 標準アドオンの string（文字列）・array（配列）・dictionary（辞書型）が使用できます。

スクリプトの基本形

1つの .as ファイルの中に、インターフェース ScriptComponentBehavior を実装したクラスを1つ定義します。ScriptComponent はビルド後にモジュール内からこのインターフェースを実装したクラスを探してインスタンス化し、以降のライフサイクル関数を呼び出します。 

// AlwaysRotate.as
// 毎フレーム一定の角速度でオブジェクトを回転させ続けるだけのスクリプト
class AlwaysRotate : ScriptComponentBehavior {
    // 各軸の角速度（ラジアン/秒）
    [SerializeField]
    Vector3 angularVelocity = Vector3(0.0f, 0.0f, 1.0f);

    void Update() {
        Transform@ tf = GetTransform();
        if (tf is null) return;

        float dt = GetDeltaTime() * GetGameSpeed();
        if (dt < 0.0f) dt = 0.0f;

        tf.SetRotate(tf.GetRotate() + angularVelocity * dt);
    }
}

クラス名はファイル名と一致させる必要はありませんが、慣習として一致させます。GetTransform() や GetDeltaTime() のようにオブジェクトを介さず直接呼べているグローバル関数は、後続ページの「スクリプトAPIリファレンス」で一覧にしている、エンジンが登録したグローバル関数です。

Behaviorクラスは1モジュール1つ
ScriptComponentBehavior を実装したクラスが1つの .as ファイル（#includeで取り込んだファイルを含むモジュール全体）に複数ある場合、最初に見つかった1つだけが使用されます。

ファイルの分割（#include）

他の .as ファイルを取り込むために #include ディレクティブが使用できます。 

// Assets/Scripts/Player.as
#include "Utils/MathHelpers.as"

class Player : ScriptComponentBehavior {
    void Update() {
        float smoothed = SmoothStep(0.0f, 1.0f, 0.5f); // MathHelpers.as で定義した関数
    }
}
  • 相対パスで指定した場合、#include を書いたファイルと同じディレクトリからの相対パスとして解決されます（ネストしたincludeも、そのファイル自身の場所を基準に解決されます）。
  • 絶対パス（C:\... やスラッシュ始まり）を指定した場合はそのまま使用されます。
  • 同じファイルが複数箇所からincludeされても二重に取り込まれません。
  • includeされたファイルもコンパイルエラー時のメッセージ（ファイル名・行番号）に反映されます。

VSCodeでのコード補完（as.predefined）

スクリプトエンジンの初期化時に、登録済みの全API定義を書き出した as.predefined ファイルが実行ディレクトリ（Assets フォルダと同じ階層）へ自動生成されます（内部関数は GenerateScriptPredefinedFile()）。VSCodeの AngelScript Language Server 拡張機能はこのファイルを読み込んでコード補完・型チェックを行うため、スクリプトを含むフォルダをVSCodeで開くだけでエンジンAPIの補完が有効になります。

補完に迷ったら as.predefined を見る
エンジン側のバインディングを変更した場合は、エンジンを一度起動すると最新の内容で再生成されます。このリファレンスは登録内容の抜粋・整理ですが、as.predefined を見れば現在ビルドに登録されている全シグネチャを確認できます。
