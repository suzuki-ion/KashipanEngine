VS CodeによるAngelScriptデバッグ

KashipanEngineのDebug/Developmentビルドは、ゲーム用 ScriptComponent と EditorTool を対象とする技術検証版のDebug Adapter Protocol（DAP）サーバーを内蔵しています。VS Codeからブレークポイントを張って実行を止め、変数の中身を確認できます。

対応機能

  • .asファイルに設定した行ブレークポイント
  • Continue / Pause
  • Step In / Step Over / Step Out
  • 停止位置とコールスタックの表示
  • ローカル変数、thisメンバー、グローバル変数の表示
  • 配列、スクリプトオブジェクト、登録済み値型の子要素表示
  • Assets以下のゲームスクリプトと EditorTools以下のEditorToolスクリプト
未対応の機能
条件付きブレークポイント、ログポイント、ウォッチ式の評価、変数の書き換えは技術検証版では未対応です。

使用手順

  1. VS Codeへ AngelScript Language Server（sashi0034.angel-lsp）をインストールします。
  2. VS Codeでこのリポジトリの Project フォルダーを開きます。
  3. KashipanEngineをDebugまたはDevelopmentビルドで起動し、デバッグ対象のシーンを開きます。
  4. VS Codeの「実行とデバッグ」から Attach to KashipanEngine AngelScript を開始します。
  5. AssetsまたはEditorTools以下の.asファイルへブレークポイントを設定し、ゲームを実行するかEditorToolを操作します。
接続先
DAPサーバーは localhost:27979 だけで待ち受けます。正常に開始するとエンジンログへ「AngelScript DAP: localhost:27979 で待受を開始しました」と出力されます。
Debug構成での動作確認について
Debug構成はExecuteCommandListsで既存の初回フレームクラッシュがあるため、通常の動作確認はDevelopment構成で行ってください。AngelScriptデバッグ自体はDebug/Developmentどちらのビルドでも利用できます。

制限事項

  • ブレークポイント停止中はAngelScriptを実行しているエンジンのメインスレッドも停止します。
  • 同じスクリプトを複数の ScriptComponent が使用している場合、ブレークポイントは全インスタンスへ適用されます。
  • Releaseビルドではデバッグサーバーを開始しません。
  • 別のプロセスが27979番ポートを使用している場合、DAPサーバーは開始されません。
