# KashipanEngine CPU Profiler

Python製の外部CPUプロファイラーです。GPU計測は扱いません。
Python 3.10以降とTkinterが必要です。通常のWindows版PythonにはTkinterが含まれます。
追加のpipパッケージは不要です。

## 起動

ビルド済みエディターの **デバッグウィンドウ → 外部CPUプロファイラーを起動** から開けます。
Python 3.10以降とTkinterが必要です。GUI起動用の`pyw.exe -3`／`pythonw.exe`を優先し、なければ`py.exe -3`／`python.exe`を探索して、コンソールを表示せずに起動します。
エンジンと同じ`KASHIPAN_PROFILER_PORT`を渡します。通信が無効の場合はエラーを表示します。
起動中はメニュー項目が無効になり、閉じると再起動できます。手動起動を含め、Windowsでは同じポートのアプリを重複起動しません。
Pythonの不在や起動失敗はエディターのダイアログとログで通知します。
開発時はエンジンルート、配布時は実行ファイル側の`Tools/Profiler`を使用します。
Development配布にはアプリ本体を同梱しますが、Python自体の同梱は行いません。
エディターを閉じてもプロファイラーは起動したままです。

1. 今回の変更を含むKashipanEngineをビルドして起動します。
2. このフォルダーの `StartProfiler.cmd` をダブルクリックします。
3. 自動で `127.0.0.1:47180` に接続します。先にアプリを開いても、エンジン起動まで再接続します。

ターミナルから起動する場合:

```powershell
python Project/Tools/Profiler/profiler.py
```

保存した記録だけを確認する場合:

```powershell
python Project/Tools/Profiler/profiler.py --offline
```

エンジン本体の再ビルドが必要です。変更前の実行ファイルはデータを送信しません。
待ち受け先はlocalhost固定で、LANには公開しません。接続できるビューアーは1つです。
Debug / Development / Releaseで同じ通信機能を使います。

## 操作

- **接続／切断**: 自動再接続を開始・停止します。エンジンの終了操作は送りません。
- **一時停止**: 表示と履歴への取り込みを止めます。通信の受信は続け、停止中のデータは破棄します。
- **ライブに戻る**: 最新のサンプルを取り込みます。停止中の期間は復元しません。
- **グラフ／スライダー**: 一時停止して過去の受信サンプルを選択します。
- **処理一覧**: 列見出しで並べ替え、処理名で検索できます。行を選ぶと緑色のグラフにその処理の直近時間を重ねます。
- **履歴を保存／読み込み**: 最大600件の受信履歴をJSON Lines形式で保存します。読み込み時は通信を切断します。

青いグラフはフレーム時間、緑は選択した処理です。60 FPS相当の16.67 msを破線で表示します。
通信を再接続すると、最初の新しいサンプルを受信した時点で古いセッションの履歴をクリアします。

## 計測の意味と制限

約100 ms間隔で、その時点の最新完了フレームと集計値を送信します。
**全フレームの記録ではありません**。フレーム番号の飛びは通常発生します。
600件は約60秒分ですが、停止や通信状況によって期間は変わります。
受信時刻はPython側の時刻で、エンジン内の計測時刻ではありません。

直近・呼び出し回数は送信時点の最新完了フレーム、平均・最大はエンジンが保持する
直近1〜600フレームの集計です（既定60、エンジン内プロファイラーの設定と共通）。
記録ファイルもこの集計結果を保存します。フレーム間のスパイクはグラフに現れない場合があります。

CPU経過時間にはPresentや同期の待機が含まれます。CPUの実稼働時間やGPU実行時間とは異なります。
入れ子の処理は子の時間を含むため、行を合計してもフレーム時間にはなりません。
スレッド別タイムライン、開始・終了時刻、処理の親子関係は記録しません。

シリアライズと送信は専用スレッドで行い、ゲームのメインスレッドでは通信を待ちません。
ただし計測結果のコピーには既存Profilerのロックを短時間共有し、CPU・メモリ使用量も増えるため、
接続の影響が完全にゼロになるわけではありません。性能への影響は実際のゲームで比較してください。
未接続中は計測結果を集計・シリアライズしません。

送信待ちは1パケットまでです。2秒間送信が進まない接続は切断します。
アプリ側の受信キューは64件、履歴は600件、1パケットは1 MiB、保存ファイルは64 MiBを上限とします。
受信キューがあふれた場合は古いイベントを破棄して件数を表示します。
新しい完了フレームが届かない場合は最終受信からの経過時間を表示します。

## ポート設定

エンジン起動前に環境変数を設定します。`0` は送信機能を無効にします。
未設定は47180、不正な値は無効扱いです。ポート使用中はゲームを続行し、起動ログへ通知します。

```powershell
$env:KASHIPAN_PROFILER_PORT = '47181'
# このPowerShellからエンジンを起動
python Project/Tools/Profiler/profiler.py --port 47181
```

接続できない場合は、再ビルド済みか、エンジンの起動ログ、ポートの一致、他のビューアーの接続、
セキュリティソフトのローカル通信制限を確認してください。

## 通信仕様 v1

UTF-8のJSONを1行1パケット（末尾LF）で送ります。クライアントからのコマンドは受け付けません。
`type: "kashipan.cpu"`, `version: 1`, `pid`, `frameId`, `frameMs`, `fps`, `frames`,
`sampleCount`, `results` を含みます。処理行は `name`, `milliseconds`, `averageMs`, `peakMs`, `calls` です。
`frameId` は完了フレームの連番、`frames` は平均・最大の集計対象フレーム数です。
保存時は `receivedAt`（Unix秒）と `session` を追加し、先頭行に
`{"format":"kashipan.cpu.capture","version":1}` を記録します。
